一个 AgentConnect 个人资料可以同时绑定多种社交登录方式。AgentConnect Cloud 目前支持 **GitHub**、**Google** 和 **Slack**；自托管部署还可以按[登录](/self-hosting/sign-in#lark-and-feishu-identities)文档中的说明额外配置 **Lark** 和**飞书**身份。

关联新的提供方后，你的个人资料会多一种登录方式；在受支持的平台上，还会提供对应的平台身份用于特定的权限检查。但关联**不会**把不同平台的权限合并到一起。

打开右上角头像菜单 → **个人资料**，找到**登录方式**。

<Image src={imgSocialSignInMethods} alt="多种登录方式关联到同一个 AgentConnect 个人资料" width={760} />

通过组织的[单点登录](/operate-govern/single-sign-on)创建的登录方式会在此处显示为 **SSO** 并附带对应邮箱。它不属于关联的社交账号：无法在这里解除关联，也不会为下文的权限检查提供任何第三方平台身份。

## 关联账号 [#link-an-account]

点击某个提供方旁的**关联**并完成授权流程。GitHub 和 Google 无需所有权验证码；Slack 和标准 OAuth 连接器可能会先要求输入发送至当前个人资料已验证主邮箱的验证码（在自托管部署上，请向运维人员确认是否已配置邮件验证）。

关联完成后，你可以用任意已关联的提供方登录，访问同一个 AgentConnect 个人资料、组织、成员身份和个人设置。

如果某个第三方账号已经绑定到另一个 AgentConnect 个人资料，则不能重复关联到当前资料。AgentConnect 会拒绝本次关联，两个个人资料均保持不变。

## 解除关联 [#unlink-an-account]

点击已连接提供方旁的**解除关联**。每个个人资料必须保留至少一种社交登录方式，因此最后一个已关联的提供方无法移除。

解除关联只会移除该登录方式及对应的平台身份：

- **GitHub**：不会卸载 GitHub App，也不会删除现有的 Agent 或仓库授权。你仍然可以以只读方式选择公开仓库，但在重新关联 GitHub 前，无法验证私有仓库或写入权限，也无法查看同步的私有仓库会话。公开仓库会话不受影响。
- **Google**：仅移除 Google 登录选项，不涉及任何平台专属权限。
- **Slack**：会立即从权限校验中移除该工作区身份。现有的 Slack 会话记录不会被删除，但依赖该身份匹配的私有私信和按 Slack 范围共享的会话将不再可见。重新关联同一工作区身份后即可恢复可见，无需重写会话。
- **Lark 或飞书**：仅移除该地区身份。匹配的私有私信和按成员关系限定的会话在重新关联同一身份前不可见。

## 关联永远不会改变什么 [#what-linking-never-changes]

关联或解除关联任何提供方，都不会改变以下内容：

- AgentConnect 个人资料 ID；
- 组织成员身份或角色；
- Agent、Daemon、定时任务、工具或技能的[团队可见范围](/operate-govern/permissions-overview/team-visibility)；
- 现有的资源共享授权；
- 其他提供方的权限。

有一个针对受限 Agent 的例外情况值得留意：如果某位成员已经在该 Agent 的共享范围内，并且关联了同一工作区的 Slack 身份，那么他与该 Agent 的 **1:1 Slack 私信**会采用普通私信的默认设置，而不是默认**关闭**。这两个条件必须同时满足：未关联身份的共享成员，以及已关联身份但不在共享范围内的成员，其私信仍保持**关闭**。该规则仅适用于 Slack 的 1:1 私信，不适用于频道或群组私信；它会在账号关联完成或共享范围扩大时重新评估，绝不会重新打开被编辑者手动关闭的对话，也不会关闭已经开启的对话。受限 Agent 的其他部分（包括频道访问）仍默认处于**关闭**状态。

关联账号也不会合并两个 AgentConnect 个人资料，不会安装 GitHub App、授权仓库或安装聊天机器人。完整权限边界请参见[权限](/operate-govern/permissions-overview)。

## 每个提供方带来什么 [#what-each-provider-adds]

| 提供方 | 带来 | 不带来 |
| --- | --- | --- |
| **GitHub** | 登录，以及用于设置和会话检查的 GitHub 身份 | App 安装或仓库访问权限 |
| **Google** | 登录 | 提供方专属授权 |
| **Slack** | 登录，以及一个用于会话检查的工作区身份 | 机器人安装或跨工作区身份 |
| **Lark** | 登录，以及用于受支持会话检查的地区身份 | 机器人安装或飞书身份 |
| **飞书** | 登录，以及用于受支持会话检查的地区身份 | 机器人安装或 Lark 身份 |

已关联的 Slack 身份可用于匹配私有 Slack 私信会话的所有者，也会在组织启用**遵循 Slack 访问权限**时用于成员校验。当 Logto 记录中包含跨应用 `union_id` 时，已关联的 Lark 或飞书身份在其聊天中的作用方式相同。因此，关联匹配的账号可以让已有会话恢复可见，解除关联则会取消匹配。详情见[会话可见范围](/operate-govern/permissions-overview/session-visibility#session-access)。

开启**遵循 Slack 访问权限**后，当 Agent 编辑者在 Slack 中响应审批或修改设置时，AgentConnect 同样通过已关联的 Slack 身份识别其编辑权限（Lark 和飞书同理）。尚未关联账号的编辑者会被拒绝操作，并收到关联指引。详情见[聊天中可以做什么](/build-your-team/agents/configure-an-agent#what-people-can-do-in-chat)。

无论**会话访问权限**如何配置，关联 Slack 账号还能让 Agent 代表你跨平台操作。当你在 Slack 中让 Agent 处理另一个平台上的对话，或调用该 Agent 的另一个机器人时，AgentConnect 会通过已关联的 Slack 账号识别你的身份。反之，当你从其他入口（例如 Playground 或该 Agent 的其他机器人）查询该 Slack 工作区中的对话时，Agent 会依据你关联的 Slack 身份校验权限：公开频道要求你是正式成员，私密频道或群组私信要求你是对话成员。未关联账号时，从 Slack 发起的请求只能访问当前机器人自身的对话。在自托管部署中，已关联的 Lark 或飞书账号同样适用。详情见[在其他对话中读取和发消息](/connect-automate/integrations-overview#reading-and-posting-in-other-conversations)。

### 两项 GitHub 策略以不同方式使用该身份 [#two-github-policies-use-the-identity-differently]

- **按用户的仓库授权**：在配置仓库时检查当前登录用户。未关联 GitHub 账号时，仍可以只读方式选择公开仓库；选择私有仓库需要拥有访问权限的已关联 GitHub 账号；使用**读写**权限始终要求已关联的 GitHub 用户具备该仓库的 `write` 或 `admin` 权限。
- **要求 GitHub 访问权限**：控制谁可以查看由 GitHub 触发的会话。公开仓库会话不需要关联身份；私有仓库会话需要当前拥有仓库访问权限的已关联 GitHub 账号。

仓库选择器和 GitHub 事件集成仍然要求部署的 GitHub App 已安装并覆盖目标仓库（公开仓库也可以在未安装 App 的情况下作为匿名只读工作区使用）。无论是关联账号还是这两项策略，都不会单独授予仓库访问权限。

GitHub Webhook 授权则是单独校验的：AgentConnect 会检查 Issue、Pull Request 或评论作者当前的仓库权限。控制台登录用户所关联的 GitHub 账号，不会赋予其他 GitHub 作者触发 Agent 的权限。详情见 [GitHub](/connect-automate/triggers-automation/github)。

## 检查始终针对特定提供方 [#checks-stay-provider-specific]

| 权限检查 | AgentConnect 使用的身份 |
| --- | --- |
| GitHub 设置或私有仓库会话 | 已关联的 GitHub 个人资料 |
| Slack 私信或共享对话 | 已关联的 Slack 工作区个人资料 |
| Lark 或飞书对话 | 已关联的地区个人资料；开启“遵循访问权限”时校验当前成员关系 |

关联多种登录方式可以让同一个 AgentConnect 个人资料分别通过多项独立检查，但不能让一个提供方替代另一个。Google 始终仅用于登录（不附带任何平台专属授权），公开的 GitHub 会话则始终对所有组织成员可见，不受所属 Agent 团队可见范围的限制。

AgentConnect 不会跨平台或跨工作区合并权限。具体来说：

- 一个社交账号不能证明你对另一平台会话的所有权；
- 一个平台的账号不能用于通过另一平台的仓库或对话访问检查；
- 单个 Slack 身份只对应当前工作区，不代表其他工作区的同一用户；按应用隔离的 Lark 或飞书身份也不能直接匹配所有机器人应用；
- 关联任何提供方都不会扩大组织访问权限或资源可见范围。

## AgentConnect OSS 设置 [#agentconnect-oss-setup]

AgentConnect OSS 默认不启用社交登录。如需支持关联账号，请在 Setup 中初始化基于 Logto 的登录，启用需要展示的登录方式，并配置对应的 Logto 连接器。启用 OIDC 登录后，个人资料页上才会显示登录方式卡片。

运维人员还需要开启 Logto 账号关联、配置提供方身份查询，并为需要所有权验证码的提供方配置邮件发送服务。本地无认证模式不会推断已关联的提供方身份。

完整配置步骤见[登录](/self-hosting/sign-in#link-additional-social-accounts)。
