共享 Slack 机器人可以让同一个 Slack 应用服务多个 AgentConnect Agent。团队成员只需要邀请并 `@` 这一个机器人，AgentConnect 会将每个频道的消息自动路由给该频道对应的默认分发 Agent。

<Image src={imgSlackIntegration} alt="创建一个可以在多个 Agent 之间共享的 Slack 机器人身份" width={640} />

当不同频道需要搭配不同的模型、代码仓库、工具或提示词，而又不想为每个 Agent 单独装一个 Slack 应用时，这种配置非常实用。

这对应[多 Agent 工作模式](/build-your-team/agents/multi-agent-work-modes#shared-bot-with-contextual-routing)中的按上下文路由：每条入站消息只交给一个选定的 Agent 处理，不会广播给所有 Agent。

| Slack 对话         | 默认分发            | 触发条件       | 示例角色                 |
| ------------------ | ------------------- | -------------- | ------------------------ |
| `#engineering`     | `engineering-agent` | **所有消息**   | 功能实现与仓库开发       |
| `#security`        | `security-agent`    | **@ 提及**     | 威胁分析与敏感评审       |
| `#support`         | `support-agent`     | **所有消息**   | 产品咨询与 Issue 分诊    |

## 开始之前 [#before-you-start]

你需要准备：

- 两个或更多在线 Agent
- 在目标 Slack 工作区中创建或安装 Slack 应用的权限

在 AgentConnect Cloud 上，基于 Relay 的 Slack 投递已默认就绪。共享机器人必须使用 **HTTP (Events API)**，因为 Socket 模式的机器人绑定在单个 Daemon 上，无法在多个 Agent 之间共享。

AgentConnect OSS 运维人员需要先配置[公开的 Relay URL](/self-hosting/docker-compose/configuration#network-and-public-urls)，再创建 Slack 应用。

## 1. 创建按频道划分的 Agent [#1-create-the-channel-specific-agents]

为每种分工分别创建一个 Agent，并在各自页面上配置模型、指令、工作区、工具和权限。

把角色差异留在各自的 Agent 配置中，不要把所有逻辑塞进一个按频道名做分支的大提示词里，让共享机器人的频道路由直接命中已经分工明确的 Agent。

例如：

- `engineering-agent` 使用编码模型，拥有主仓库的写入权限
- `security-agent` 使用推理能力更强的模型，只读访问仓库，并搭配聚焦安全评审的提示词
- `support-agent` 使用快速模型，并接入产品文档工具

## 2. 让 Slack 机器人可共享 [#2-make-the-slack-bot-sharable]

### AgentConnect Cloud [#agentconnect-cloud]

从内置应用开始：

1. 在内置的 `agentconnect` Agent 上，选择 **集成 → 添加集成 → Slack → 添加到 Slack** 并批准工作区安装。如果已经连接，可以跳过这一步。
2. 打开 **集成 → 消息应用 → Slack**。
3. 为内置的 AgentConnect 机器人开启 **可共享**。

Cloud 应用默认使用 HTTP 投递，无需手动配置回调 URL、签名密钥或传输方式。

### 自定义应用或自托管部署 [#custom-app-or-self-hosted-deployment]

在第一个 Agent 上，打开 **集成 → 添加集成 → Slack**：

1. 使用配置令牌或 manifest 流程创建一个 Slack 应用。
2. 将 **投递方式** 设为 **HTTP (Events API)**。
3. 开启 **共享机器人——允许多个 Agent 使用此机器人**。
4. 完成 Slack 安装并将其连接到该 Agent。

使用配置令牌流程时，AgentConnect 会自动获取签名密钥；使用 manifest 流程时，请从 Slack 应用设置中复制粘贴机器人令牌和签名密钥。

将应用邀请进需要服务的每个频道：

```text
/invite @your-bot
```

Slack 上报机器人的成员关系后，这些频道就会出现在 AgentConnect 中。

## 3. 把同一个应用连接到其他 Agent [#3-connect-the-same-app-to-the-other-agents]

对其余每个 Agent 重复以下步骤：

1. 打开 **集成 → 添加集成 → Slack**。
2. 选择 **使用已有机器人**。
3. 选中刚才创建的共享机器人。
4. 将其连接到该 Agent。

不需要再创建新的 Slack 应用。现在所有关联的 Agent 共用同一个 Slack 机器人身份和凭证，同时各自运行在自己的 Daemon 上。

## 4. 分配每个频道 [#4-assign-each-channel]

打开 **集成 → 消息应用 → Slack** 并展开共享机器人，为每个频道指定 **默认分发** Agent。如果希望按对话内容动态决定由哪个 Agent 接手，请选择 **或按决策选择**，通过[决策](/build-your-team/decisions#route-a-shared-bot)进行路由。

接着，在任意一个已连接 Agent 的 Slack 集成页面中设置频道触发条件。触发条件作用于“共享机器人 + 频道”这一组合，因此 AgentConnect 会将同一设置同步应用到所有关联该机器人的 Agent 上：

- **@ 提及**：仅在被 `@` 时触发；在 Agent 已加入的线程（thread）中，后续未 `@` 的跟进消息会继续由它处理。
- **所有消息**：频道中的每条消息都触发默认 Agent。
- **关闭**：停止该共享机器人在这个频道中的所有入站路由，包括 `@` 提及、已有线程以及回退到同级或默认 Agent。受限 Agent 在频道中也默认关闭，直到编辑者手动启用。

每个启用中的共享机器人频道都有且仅有一个默认分发 Agent。在控制台中更改默认分发 Agent 时，该频道的触发条件会原样保留。

## 路由行为 [#how-routing-behaves]

1. 频道的默认分发和触发条件共同决定新消息交给哪个 Agent。
2. 线程一旦分配给某个 Agent，后续未 `@` 的跟进消息会继续留在该 Agent。
3. 回复均以同一个 Slack 应用身份发出。如果开启了回复页脚，页脚会标明实际回复的 AgentConnect Agent、Runtime 和模型。
4. Agent 不会触发自己：AgentConnect 会在消息回流前丢弃每个 Agent 自己发出的消息。

频道中一条未指名的新消息只会路由给**一个** Agent，也就是该频道的默认分发 Agent。共享机器人的作用是在同一个身份背后按频道路由到不同的专项 Agent，而不是把消息广播给所有 Agent 同时回复。

如果有人明确将另一个关联此共享机器人的 Agent 引入同一条线程，两个 Agent 仍各自保留独立的会话和配置。如果需要让它们之间直接委派任务，请配置 [Agent 可见范围](/operate-govern/permissions-overview/agent-visibility)。

## 故障排查 [#troubleshooting]

| 症状 | 检查项 |
| --- | --- |
| **可共享** 不可用 | 确认使用 HTTP 投递且 Relay 在线（Cloud 已预配） |
| 缺少某个频道 | 邀请或重新邀请机器人，等待成员关系同步 |
| 回答的 Agent 不对 | 检查 **默认分发** 与频道触发条件 |
| 后续消息仍由上一个 Agent 处理 | 开启新线程或在会话中切换 Agent |

安装细节见 [Slack](/connect-automate/chat-platforms/slack)，模型、提示词、工作区和权限配置见[配置 Agent](/build-your-team/agents/configure-an-agent)。
