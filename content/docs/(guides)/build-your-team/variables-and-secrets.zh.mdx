变量和密钥会以环境变量的形式注入 Agent 的 Runtime。你可以在组织级定义一次供多个 Agent 共享，也可以仅配置在单个 Agent 上。

<Image src={imgVariablesSecretsForm} alt="创建组织变量或只写密钥" width={520} />

| 范围 | 管理位置 | 适用于 |
| --- | --- | --- |
| 组织 | **设置 → 变量与密钥** | 所有或选定的 Agent |
| Agent | Agent → **配置** | 单个 Agent |

变量适合存放服务端点、功能开关等非敏感配置；密钥用于凭证以及其他保存后不应再次明文展示的值。

## 在多个 Agent 之间共享一个值 [#share-a-value-across-agents]

仅组织所有者可以管理组织级条目：

1. 打开**设置**，找到**变量与密钥**。
2. 点击**添加**，选择**变量**或**密钥**。
3. 输入标准环境变量名（例如 `SERVICE_URL` 或 `SERVICE_API_KEY`）及对应的值。
4. 选择**所有 Agent**或**选定 Agent**。
5. 保存条目。

名称支持字母、数字和下划线，不能以数字开头。

选择**所有 Agent**会将该条目分配给你有管理权限的所有 Agent，并自动应用于后续新建的 Agent。选择**选定 Agent**则仅作用于勾选的 Agent。选择器只列出你能管理的 Agent，调整勾选范围不会移除已分配给其他私有 Agent 的记录。

已分配的条目会显示在 Agent 的变量或密钥卡片中，带有**组织**标签且为只读。组织所有者在**设置**中统一编辑或轮换；其他 Agent 编辑者仍可继续管理该 Agent 的本地条目。

## 在单个 Agent 上设置一个值 [#set-a-value-on-one-agent]

打开 Agent 的**配置**标签页，编辑其中的**变量**或**密钥**卡片，添加的条目仅对当前 Agent 生效。

创建 Agent 时，最后一步的**变量和密钥**添加的也是这类 Agent 本地条目；同时，作用范围为**所有 Agent**的组织条目会在创建时自动应用。

## 优先级 [#precedence]

当 Agent 本地存在与已分配的组织条目同名的配置时，通常由组织条目覆盖：

| 组织条目 | Agent 条目 | 生效值 |
| --- | --- | --- |
| 变量 | 变量 | 组织变量 |
| 密钥 | 变量或密钥 | 组织密钥 |
| 变量 | 密钥 | 拒绝 |

最后一种组合会被拒绝，避免可读的普通变量覆盖只写密钥。被覆盖的 Agent 本地条目会作为后备保留下来，在移除或删除组织级分配后自动恢复生效。

组织级的名称在变量和密钥之间统一唯一。创建后名称和类型均不可修改；如需改名或更换类型，请先删除再重新创建。

## 密钥处理 [#secret-handling]

密钥值为只写。保存后，AgentConnect 只展示名称和掩码；编辑时只提供**替换值**操作，无法回读原值。变量值对有权查看对应 Agent 的成员均可见，因此切勿将凭证存为普通变量。

“只写”限制的是通过产品界面或 API 的读回行为，不代表底层所有环节的存储方式。使用 AgentConnect OSS 时，请配置[密钥存储加密](/self-hosting/docker-compose/configuration#secret-storage)以保护控制平面数据库中的静态数据。运行 Agent 的 Daemon 会在该 Agent 的本地配置文件中保存一份解析后的值，运行 Daemon 的操作系统用户可读取该文件。因此，接入的每台机器都应视为被信任持有其上所部署 Agent 的密钥。

密钥对 Agent Runtime 及其工具可见。如果 Agent 输出中出现已知的密钥字面值，AgentConnect 会尝试自动打码，但打码不能当作安全边界。请按最小权限原则仅授予每个 Agent 必需的密钥，并配合合理的[权限](/operate-govern/permissions-overview)与[沙箱隔离](/operate-govern/sandboxing)。

变量和密钥只作为环境变量注入进程，不会展开 Agent 描述、定时任务、集成设置或其他配置字段中的占位符。

### Kubernetes 和 Docker 凭证 [#kubernetes-and-docker-credentials]

有两个特殊名称会改为写入文件后传递路径，因为对应工具需要文件路径而不是直接读取环境变量值：

| 你设置的 | Agent 的工具得到的 |
| --- | --- |
| `KUBECONFIG_DATA` | `KUBECONFIG`，指向生成的 kubeconfig 文件 |
| `DOCKER_CONFIG_DATA`（或较旧的 `DOCKER_AUTH_CONFIG`） | `DOCKER_CONFIG`，指向生成的配置目录 |

将文件完整内容填入 `…_DATA` 密钥即可。Agent 运行期间，AgentConnect 会把内容写成仅所有者可读的本地文件，并让 `kubectl` 或 `docker` 指向该路径。`…_DATA` 密钥和对应的路径变量二选一即可，不要同时配置。

## 更新与移除 [#updates-and-removal]

轮换、调整分配范围或删除组织条目时，系统会更新受影响的 Agent 并重启它们，使后续任务加载新环境。若不希望打断正在进行的轮次，建议选在空闲时段操作。

移除组织级分配后，同名的 Agent 本地后备值会自动恢复生效；若没有后备值，该环境变量会在后续的 Runtime 进程中消失。
