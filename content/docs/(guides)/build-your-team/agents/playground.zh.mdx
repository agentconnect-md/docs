Playground（控制台中显示为“试用”）是在浏览器中与运行在你的 Daemon 上的 Agent 进行的私密对话。从 Agent 页面打开它可开始单 Agent 会话，或者使用首页输入框把多个 Agent 带进同一个对话。

<Image src={imgPlayground} alt="首页输入框中选择了多个 Agent，用于同一个 Playground 对话" width={780} />

## 你会得到什么 [#what-you-get]

Playground 会在 Agent 的 Daemon 上创建一个真实的会话，使用与频道对话相同的 Runtime、工作区和工具。它的输出会流式写入同一种[会话记录](/operate-govern/sessions)。

你可以为下一轮更改受支持的 Runtime 设置，而不改动 Agent 已保存的配置，也可以在需要时中断某一轮。

## 在对话中配置 AgentConnect [#configure-agentconnect-from-a-conversation]

在只有一个 Agent 的 Playground 对话中，这个 Agent 可以读取当前设置，并用与 [MCP 连接器](/connect-automate/mcp-connector)相同的工具替你做出更改。它以你的身份行事，因此你的角色和[可见范围](/operate-govern/permissions-overview)同样适用。每项更改都会以审批卡片的形式出现在输入框上方，列出确切的参数；在你点击 **Approve and run** 之前，任何更改都不会生效。之后 Agent 会收到结果并继续。

做配置时，建议从内置的 **AgentConnect** Agent 开始，它自带介绍平台和创建 Agent 的技能。任何 Agent 也都可以用这种方式更改自己的配置和工作区，但不能删除自己。

有多个 Agent 的对话中不能使用这些工具。向对话中加入 Agent 后，该对话在余下的时间里都无法再使用它们；做配置时请新开一个只有一个 Agent 的对话。

Agent 绝不会在对话中索要凭证。创建 Agent、连接集成或代码托管、添加密钥、MCP 服务器或技能时，它会打开对应的控制台对话框，并尽量预先填好，由你来完成。在这里不能用示例消息试运行[决策](/build-your-team/decisions)；请在决策编辑器中使用**用示例试运行**。

## 与多个 Agent 协作 [#work-with-several-agents]

可以在首页输入框发送第一条消息之前添加 Agent，也可以把它们加入已有的 Playground 对话。

- 不带 `@AgentName` 的消息会发送给每个参与者。每个 Agent 可以回答，也可以保持沉默。
- 明确的 `@AgentName` 会把该轮次限定到被点名的一个或多个参与者。
- 每个 Agent 都保留自己的配置，而浏览器把它们的活动合并为一个对话。

## 会话何时被保存 [#when-the-session-is-saved]

打开 Playground 时首先是一个空的临时视图。你的第一条消息会把这次私密对话保存到 **会话** 下，之后可以在那里重新打开。

## 小贴士 [#tips]

- 在共享频道中使用 Agent 之前，先在这里测试 **权限模式**——先试试 *规划* 或 *请求审批*，观察它想做什么，然后再放宽。
- Playground 遵循 Agent 的工作区。对于基于 GitHub 的新单 Agent 对话，可以选择它的第一轮是否使用独立的工作树，而不改变 Agent 已保存的默认值。
- 如果输入框提示某个 Agent 无法访问，请检查它的 Daemon 是否在线——Playground 会话运行在参与的 Daemon 上，而不是云端。
