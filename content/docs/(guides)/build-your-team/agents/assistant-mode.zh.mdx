助理模式让 Agent 像团队里的一位同事那样工作：它在每个对话里保持一条连续的上下文，跟进大家交代给它的事，自己检查进展，有事才开口，动手之前先问。

<Callout type="info">
助理模式目前处于 Beta 阶段。
</Callout>

## 开启后有什么不同 [#what-changes]

- **每个对话一条上下文。** 每个频道、群组私信、私信和 Playground 对话都对应一个长期会话，隔了很久再来，Agent 也记得这里说过什么。Daemon 支持[自动](/connect-automate/integrations-overview#session-mode)模式时，这个会话就是该对话的协调会话：简单问题直接回答，较长的工作开成任务去做。
- **跟进。** 让它盯着某件事，它会自己回头检查，有变化时告诉你。
- **动手之前先问。** 检查中发现值得做的事，Agent 会发出提议，等人批准。
- **了解新加入的对话。** 被加进频道后，它会把近期历史读一遍，做个自我介绍，并提出几件可以帮忙的事。
- **整理组织手册。** 它对组织、各个频道以及谁负责什么的了解，会发布在**知识库**页面上，全组织共享。
- **回头看自己的工作。** 安静下来的任务会被重新捡起，或者提醒它在等的人。

其他配置保持不变：触发条件、工作区、工具，以及谁能看到和使用这个 Agent。读取和发送其他对话的内容，与所有 Agent 一样遵循[按提问人判断的规则](/connect-automate/integrations-overview#reading-and-posting-in-other-conversations)。

## 开启助理模式 [#turn-on-assistant-mode]

1. 在 **Agent** 中打开该 Agent，进入**配置**标签页。
2. 在**助理模式**面板中点击**编辑**。
3. 勾选**开启助理模式**，按需调整**限制**，然后点击**保存助理模式**。

<Image src={imgAssistantModePanel} alt="处于编辑状态的助理模式面板：已勾选开启助理模式，显示三项限制和负责人" width={640} />

如果面板显示**不可用**，它会说明需要先改什么：

- **Runtime**：Claude Code、Codex 或 OpenCode。Runtime 需要能关闭自身的记忆，并能在重启后恢复会话。
- **记忆**：**托管**。参见[记忆](/build-your-team/agents/configure-an-agent#memory)。
- **路由**：Agent 的所有对话都不能使用**按决策**，也不能经由[共享机器人](/connect-automate/integrations-overview#shared-bots)路由。面板会列出需要修改的对话。

### 开启时会改变什么 [#what-turning-it-on-changes]

- **权限模式。** 为了让没人盯着的工作不必停下来等审批，未设置、需要逐次审批或只读的权限模式，会改为该 Runtime 的自动模式（Claude Code 的 **Auto**，Codex 的 **Auto review**）；没有自动模式的 Runtime 则改为完全访问。之后你可以改成其他模式，改动会保留。如果选了每次操作都要审批的模式，面板会提示任务会经常等待审批。
- **记忆。** 保存在 Daemon 上的记忆会在同一次保存中迁移到 AgentConnect。开启期间，**记忆**标签页只提供保存在 AgentConnect 中的托管记忆。
- **会话。** 每个对话的行显示为**自动**（较旧的 Daemon 上显示为**单一会话**），不提供其他选项。触发条件不变，原本**关闭**的对话仍然关闭。
- **第一次打招呼。** 第一次开启时，Agent 会在你和它的 Slack 私信里打个招呼。组织里第一个开启的 Agent 还会调研你的组织（参见[组织手册](#the-organization-handbook)）。

关闭助理模式后，每个对话恢复到之前的会话模式；权限模式和记忆位置保持不变。

### 负责人与限制 [#responsible-person-and-limits]

面板会显示 Agent 的**负责人**：Agent 的创建者（只要他仍能编辑这个 Agent），否则是最早加入组织的编辑者。这不是一个设置项。当一项工作背后没有具体的人（例如定时任务），或者审批无法交给提问的人时，卡片会发到负责人的私信。如果负责人也联系不上，它会留在 Agent 的**动态**标签页，任何编辑者都可以在那里处理。

| 限制 | 默认值 | 作用 |
| --- | --- | --- |
| 并发的委派任务与批准后执行的提议数 | 3 | 同时在后台运行的工作数量。超出后新的工作会被拒绝，Agent 会告诉你。 |
| 每日跟进检查次数 | 50 | 任意 24 小时内启动的跟进检查次数，包括由消息触发的检查。 |
| 等待审批的小时数 | 12 | 任务等待权限请求的时长，超时后请求被拒绝，任务停止。 |

## 和它对话 [#talk-to-it]

在任何已开启的对话里，像和同事说话一样和 Agent 交流。它说话会顾及在场的人：

- 只有提问人能看到的对话，它才会替这个人去读；读到的内容要不要在当前对话里分享，由提问人决定。
- 它从你的私信里记住的内容，只会在你自己和它的对话里用到。
- 在与其他组织共享的对话里（例如 Slack Connect 频道），它和在其他地方一样回答。区别在于：这里的审批交给你所在组织的成员，这个对话有自己单独的记忆，Agent 也不会在这里被提醒你们内部的跟进事项。

如果交给它较长的工作，例如“修掉这个 bug 并开一个 PR”，它会作为任务在后台运行，完成后在对话里汇报结果。任务中途需要审批时，请求会发到你提出请求的那个对话。

## 跟进 [#follow-ups]

让它盯着某件事：“帮我盯一下 staging 的部署，正常了告诉我。”Agent 会复述它要看什么、做到什么程度算完成、下次什么时候看，你确认后它就接下这个跟进。跟进属于接下它的那个对话，结果也汇报在那里。要修改检查内容或时间，或者不再跟进，都在那个对话里告诉 Agent。

到了约定时间，Agent 会做一次**检查**。检查只看不动：它会查看状态、日志和 PR，但不修改任何东西，不发消息，也不执行需要审批的操作。每次检查有三种结果：

- 有你需要知道的变化：在对话里发一条消息。
- 有需要做的事：发出一个待批准的[提议](#proposals-and-approval)。
- 没有新情况：不说话。

跟进还可以盯住一个 GitHub PR 或 issue，或者已连接 GitLab 项目中的 merge request 或 issue。合并、评审、CI 结束或新评论都会让它在下次预定检查之前提前醒来。Agent 需要对所盯的对象有读取权限。

其他几条规则：

- 如果请求已被这个对话里某个进行中的跟进覆盖，Agent 会提议更新那一个，而不是再开一个。
- 在 Slack 上，Agent 觉得某件事值得跟进但没人提出时，会发一张卡片，而不是在回复里追问。批准卡片就会接下这个跟进。
- 连续五次检查失败后，这个跟进会停止检查，并在对话里通知一次。在那个对话里让 Agent 再检查一次即可恢复。
- Agent 暂停期间错过的检查不会补跑；恢复后，已经过期的跟进会检查一次。

## 提议与审批 [#proposals-and-approval]

检查中发现值得做的事时，Agent 会用一张卡片提出：一句话（“我想把 PR #12 rebase 到 main，因为它有冲突”）、理由，以及 **Approve** 和 **Deny** 按钮。在 Slack 上，卡片发在该跟进所属的对话里。能在那里让 Agent 干活的人都可以批准：私信里是对方本人，频道里是任何发消息就能触发 Agent 的人。批准不会额外授予任何权限，和直接开口请求一样：这项工作以任务形式运行一次，使用 Agent 自己的权限，完成后在那个对话里汇报。

在 Playground 对话里，提议会出现在输入框上方的待处理请求中。在其他平台上，以及与其他组织共享的对话里，卡片会发到负责人的私信，或者留在**动态**中。

提议在 24 小时后过期，过期后不会再执行。如果已批准的提议被重启打断，它不会被再次执行，对话里会说明结果不确定，请人去确认。

任务中途需要权限时会停下等待，请求发到任务所属的对话。如果[聊天中可以做什么](/build-your-team/agents/configure-an-agent#what-people-can-do-in-chat)允许批准工具调用，审批卡片会发在那里；否则由 Agent 编辑者在私信中处理。如果在**等待审批的小时数**内没人回应，请求会被拒绝，任务停止。

### 无人发起的运行产生的草稿 [#drafts-from-unattended-runs]

没有人发起的运行（例如定时任务或 webhook）只能直接发到它自己的对话。在助理模式下，它想发到其他地方的内容会变成草稿，由负责人通过 Slack 私信卡片或在**动态**中**批准**或**丢弃**。草稿 24 小时后过期。和所有 Agent 一样，从其他对话发往与其他组织共享的对话的内容也会先成为草稿。

## 加入频道时 [#when-it-joins-a-channel]

Agent 被加进 Slack 频道或群组私信时，会先了解一次这个地方：读取最近 30 天、最多 500 条消息，记住这里怎么运作：做什么用、大家怎么提需求、哪些事情会反复出现。它不会记下正在进行的事情，也不会记录某个人在这里的角色之外的任何信息。

然后它会做一次自我介绍：它是谁、一句话说说它看到了什么、怎么找它。下面最多列出三件它可以帮忙的事，每件都是一张卡片，能在这里让它干活的人都可以批准。它最多问一个问题，之后不会再主动发言。

对于开启助理模式之前就已在的频道，以及 Discord 和 Lark / 飞书上的对话，可以直接对它说“了解一下这个频道”。一对一私信、与其他组织共享的对话，以及不允许机器人读取历史的平台（例如 Telegram）不会进行这一步。**任务**列表里会把这次读取显示为**了解频道**。

## 组织手册 [#the-organization-handbook]

你的组织第一次开启助理模式时，Agent 会在你和它的 Slack 私信里打个招呼，然后在后台调研你的组织。它会读取自己的共享记忆、已发布的知识库、它所在频道的名称、它有权读取的代码仓库，以及公开网页。调研完成后，它会在私信里告诉你学到了什么、写下了什么、哪些读不到，以及最多两件它需要你帮忙的事。之后随时可以在那里让它重新调研。后来开启的 Agent 会直接读取第一个 Agent 写下的内容。如果你和它没有 Slack 私信，它会改为向负责人打招呼；两者都没有时，不会进行调研。

Agent 了解到的内容会写进**知识库**页面顶部的**手册**，全组织共用一份：

- **关于**：一段简短概述，然后是产品与客户、组织的运作方式，以及仓库和系统。
- **频道**：每个对话一行，写明它的用途。
- **人员**：谁负责什么、熟悉什么、什么事该问谁。

<Image src={imgKnowledgeHandbook} alt="知识库页面上的手册：列出关于、频道和人员三项，以及每项由哪些 Agent 读取" width={820} />

每一行都注明来源和日期，组织自己的来源优先于网页。手册只记录在任何对话里都可以说的内容。它会在调研时、了解公开频道时，以及有人在内部公开频道里陈述事实时更新。所有者可以在知识库页面编辑或清空任意一项。组织里的每个 Agent 都能查阅“关于”和“频道”，助理模式的 Agent 还会读取“人员”。

### 人员 [#people]

“人员”只记录工作相关的事实，且只来自内部公开频道：不记录评价、对他人工作的判断，也不记录任何来自私信、私密频道或有外部人员参与的对话的内容。在有组织外部人员的对话里，Agent 不会读取它，也不会因为其中的内容去联系任何人。

你的条目归你自己管。在私信里问 Agent 它知道你哪些信息，可以直接在那里更正或删除；也可以在**知识库 → 手册 → 人员**中你自己的卡片上修改。删除后，在你自己添加条目之前，不会再写入任何关于你的内容。有人离开组织后，其条目会自动删除。

## 查看它在做什么 [#keep-track-of-its-work]

- **直接问它。** “你手上有哪些事？”会列出这个对话的跟进、每项最近看到的情况、下次检查时间、等待审批的内容，以及正在运行的任务。
- **对话的任务标签页。** 在[会话](/operate-govern/sessions)中打开该对话的会话，可以看到它的任务和跟进、最近的检查记录，以及**停止**按钮。
- **Agent 的动态标签页。** 列出 Agent 在所有对话中的任务和跟进。编辑者还能看到所有等待审批的内容（草稿、提议和任务的权限请求），并可以在这里处理。
- **Slack 上的 Work canvas。** 在每个有进行中工作的内部 Slack 频道里，Agent 会维护一个名为 **Work** 的只读 canvas，列出该频道进行中的任务和跟进，以及发往这里的定时任务。它不会为此发消息。

每隔几个小时，Agent 会回头看一遍对话中安静下来的任务。如果某个任务问了人却没人回答，它会在任务的话题里提醒那个人；如果某个任务在交代给它的工作做到一半时停下了，它会让任务回去接着做完。被人停止的任务不会被打扰。

## 停止它 [#stop-it]

- 在对话主聊天里发 `!stop` 只会中断当前这一轮，已在运行的任务会继续。
- 要停止某个任务或跟进，在发起它的对话里点名（“把 PR 那个任务停掉”）。如果不明确指的是哪个，Agent 会先确认。也可以在任务标签页或**动态**中点击**停止**。
- 要停止所有工作，在 Agent 页面上点击**暂停**。

停止不会撤销已经完成的工作。Runtime 自己启动的后台进程（例如 dev server）可能会继续运行，Agent 会说明这一点。

## 自托管 [#self-hosting]

- Agent 所在 [Daemon 组](/build-your-team/daemons/daemon-groups)中的所有 Daemon 必须共用同一个存储。
- Agent 的记忆保存在 Control Plane 中。Control Plane 无法访问时，Agent 的记忆也不可用。
- 如果 Daemon 关闭了自动模式，每个对话会使用一个**单一会话**，而不是协调会话。
