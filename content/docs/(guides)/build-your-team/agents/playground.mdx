Playground is a private browser conversation with agents running on your daemons. Open it from an agent page for a single-agent session, or use the Home composer to bring several agents into the same conversation.

<Image src={imgPlayground} alt="Home composer with several agents selected for one Playground conversation" width={780} />

## What you get

Playground creates a real session on the agent's daemon, using the same runtime, workspace, and tools as a channel conversation. Its output streams into the same kind of [session transcript](/operate-govern/sessions).

You can interrupt a turn when needed. When the agent's [**What people can do in chat**](/build-your-team/agents/configure-an-agent#what-people-can-do-in-chat) is **Talk, approve and change settings**, you can also change supported runtime settings for the next turn without altering the agent's saved configuration. A tool call that needs approval waits among the pending requests above the composer. The agent's editors can answer it at any level, and from **Talk and approve tool calls** up, so can you as the conversation's owner, even if you can only view the agent.

When you ask the agent to read or post in a chat conversation, it does so for you, by the same rule as in chat; see [Reading and posting in other conversations](/connect-automate/integrations-overview#reading-and-posting-in-other-conversations). In a workspace where you linked your chat account under **Your profile → Sign-in methods**, such as your Slack account, it judges you by that account: a public channel needs you to be a full member, and a private channel or group DM needs you to be a member. Anywhere else, including Telegram and Discord, whose accounts can't be linked, you reach only conversations whose sessions you can open under **Sessions**.

## Configure AgentConnect from a conversation

In a Playground conversation with a single agent, that agent can read your setup and make changes for you with the same tools as the [MCP connector](/connect-automate/mcp-connector). It acts as you, so your role and [visibility](/operate-govern/permissions-overview) apply. Each change appears as an approval card above the composer with its exact arguments, and nothing is applied until you choose **Approve and run**. The agent is then told the result and continues.

Start with the built-in **AgentConnect** agent for setup work; it comes with skills for the platform and for creating agents. Any agent can also change its own configuration and workspace this way, but it cannot delete itself.

These tools are not available in a conversation with several agents. Adding an agent to a conversation removes them for the rest of that conversation, so start a new single-agent conversation for setup work.

The agent never asks for credentials in chat. To create an agent, connect an integration or code host, or add a secret, MCP server, or skill, it opens the matching console dialog, prefilled where it can, for you to finish. Trying a [Decision](/build-your-team/decisions) on a sample message is not available here; use **Try with an example** in the Decision editor.

## Work with several agents

Add agents before the first message from the Home composer, or add them to an existing Playground conversation.

- A message without an `@AgentName` goes to every participant. Each agent may answer or stay silent.
- An explicit `@AgentName` narrows that turn to the named participant or participants.
- Every agent keeps its own configuration while the browser combines their activity into one conversation.

## When the session is saved

Opening Playground starts with an empty, temporary view. Your first message saves the private conversation under **Sessions**, where you can reopen it later.

## Tips

- Test **permission modes** here before using an agent in a shared channel — try *Plan* or *Ask for approval* first, watch what it wants to do, then relax. Switching the mode from the composer needs **Talk, approve and change settings**; otherwise change it in the agent's **Edit**. Before the agent joins a public group, set it to **Talk to the agent**, so nobody there can approve its tool calls.
- The Playground respects the agent's workspace. For a new single-agent conversation backed by GitHub, choose whether its first turn uses an isolated worktree without changing the agent's saved default.
- If the composer reports an agent as unreachable, check its daemon is online — Playground sessions run on the participating daemons, not in the cloud.
