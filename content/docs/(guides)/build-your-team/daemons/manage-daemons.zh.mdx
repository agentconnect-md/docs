**基础设施**页面的 **Daemon** 列表展示了连接到你组织的所有机器。点进任意一台即可查看它的健康状况、可用 Runtime、资源、托管的 Agent、能力和可见范围。

## 状态 [#status]

| 状态 | 含义 |
| --- | --- |
| **在线** | 已连接，Agent 可访问 |
| **离线** | 已断开，Agent 不可用 |

离线 Daemon 上的会话记录在重新连上线之前无法读取。

重启或升级期间，状态会显示为**重启中**或**升级中**，直到 Daemon 恢复就绪。

## 操作 [#actions]

重启和升级只需要普通的 Daemon 编辑权限：能看到该 Daemon 的所有者或协作者都可以操作，查看者不行。

- **重启**（在线 Daemon）：排空当前任务，并让服务管理器重新启动同一版本。
- **升级**（在线 Daemon）：安装选定版本，排空并重启 Daemon，然后执行健康检查。如果升级失败，会在可行时自动回滚。版本落后的 Daemon 上会显示 **更新到 \<version\>** 徽标，点击即可发起升级。关于发布通道、主机本地升级和回滚，详见[升级 Daemon](/build-your-team/daemons/upgrade-the-daemon)。
- **重新连接**（离线 Daemon）：生成新的一次性令牌，并给出要在该主机上执行的命令。Daemon 原有的身份和 Agent 分配关系都会保留。
- **删除**（离线 Daemon）：从组织中移除该 Daemon 并吊销其密钥。上面的 Agent 会变为未分配且不活跃的状态，停止响应，直到你把它们分配到其他 Daemon。原机器上的进程和本地文件不会被删除，需要你自己在机器上停止或清理。

## 放置 [#placement]

分配到单台 Daemon 上的 Agent 只在那台机器上运行，其工作区、Runtime 进程和会话记录也都保存在本地。只要源和目标 Daemon 都在线、就绪，并且兼容该 Agent 的 Runtime、模型和 MCP 服务器，你就可以在 Agent 的**配置**标签页中迁移它。如果希望单台机器宕机时 Agent 依然可用，请改用 [Daemon 组](/build-your-team/daemons/daemon-groups)。

迁移 Agent 会按已保存的定义在目标机器上冷重建，不会复制原 Daemon 本地的工作区文件、本地记忆或会话记录。迁移前请先提交或备份本地改动，GitHub 工作区会在目标机器上重新克隆。

## AgentConnect Cloud [#agentconnect-cloud]

在 [AgentConnect Cloud](https://app.agentconnect.md) 上，Daemon 选择器中会提供一个托管选项：**AgentConnect Cloud**。把 Agent 放在这里后，它会直接运行在 AgentConnect 维护的基础设施上，无需自己准备机器、安装或登录 Runtime，也不用提供模型 API 密钥。平台内置了一组精选的 Runtime 和模型，每个 Agent 都运行在独立的隔离环境中。

在**基础设施**页面上，它显示为单独的 **AgentConnect Cloud** 条目，点开即可查看部署在云端的 Agent 和近期额度变动。与自建机器不同，云端部署不绑定某台特定主机：Agent 的工作区、记忆和会话记录都存在托管环境中，底层算力可能随时间调整。云端部署和自有 Daemon 可以在同一个组织里共存。在两者之间迁移 Agent 与普通迁移一样属于冷重建：系统会按已保存的定义重新创建 Agent，原有的工作区、记忆和会话记录不会随之转移。

### 定价 [#pricing]

云端按实际用量计费。把 Agent 放到云端本身不收费，你只需为会话产生的模型用量付费：

- **按提供方公开 API 价格计费**：与直接调用提供方 API 同价，不加价，[决策](/build-your-team/decisions)评估也包含在内。提供方调价时，云端费率同步更新。
- **从预付额度余额扣除**：用量直接从组织的预付额度中扣减。所有者可以在**账单**页面充值。余额、账目明细和分析视图详见[账单与用量](/operate-govern/billing-and-usage)。
- **无超额计费**：余额用尽后，云端 Agent 会暂停接收新的模型流量，充值后即可恢复。

运行在你自有 Daemon 上的 Agent 不会被 AgentConnect 计费：它们使用机器上配置的提供方凭证，模型流量直接在你的机器和提供方之间传输。

## 会话保留 [#session-retention]

每台 Daemon 都可以设置**过期会话**：选择常用时间窗口、输入自定义天数，或者永久保留。它控制 Daemon 保留已完成会话的记录和会话工作树的时长。本地内容过期后，控制平面依然保留会话元数据。过期后仍可查看的信息见[会话保留与清理](/operate-govern/sessions#retention-and-cleanup)。

## 故障排查 [#troubleshooting]

- **“添加 Daemon”一直停在“等待 Daemon…”**：通常是终端里的命令执行失败了。检查 Node 版本是否 ≥ 24.12（`node -v`），以及机器能否通过 HTTPS/WSS 访问控制平面 URL。
- **Daemon 显示离线，但本地进程还在跑**：查看日志（`npx -y @agentconnect.md/cli status` 会输出路径，默认是 `~/.agentconnect/logs/daemon.log`）。反复出现 `connect/handshake failed` 一般说明密钥已被吊销，请对该 Daemon 执行**重新连接**；如果该 Daemon 已被删除，请重新接入一台新的。
- **选择器里看不到某个 Runtime**：检查 Daemon 所属操作系统用户的 Runtime 安装和登录状态。使用 microsandbox 时，所选镜像里也必须安装了该 Runtime。在 Runtime 卡片里切换**主机**、**沙箱**和**虚拟机**标签页查看各策略状态；无法运行的策略会在列表位置直接显示原因。
- **某个执行策略不可用**：在 Agent 的**执行策略**选择器中悬停查看原因，并结合 Daemon 日志排查。SRT 需要相应的主机工具和用户命名空间，microsandbox 需要 KVM 和 vsock 访问权限。在 Daemon 的 `sandbox` 配置中设为 `false` 的策略会显示为已关闭。详见[沙箱隔离](/operate-govern/sandboxing#configure-the-daemon)。
