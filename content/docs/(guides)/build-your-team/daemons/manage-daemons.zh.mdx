## 状态 [#status]

| 状态 | 含义 |
| --- | --- |
| **在线** | 已连接；Agent 可达 |
| **离线** | 已断开；Agent 不可用 |

离线 Daemon 所拥有的会话记录在它重新连接之前无法获取。

重启或升级期间会显示为**重启中**或**升级中**，直到 Daemon 重新就绪。

## 操作 [#actions]

重启和升级使用普通的 Daemon 编辑权限：任何能看到该 Daemon 的所有者或协作者都可以执行。查看者不能。

- **重启**（在线 Daemon）——排空工作，并请求服务管理器以同一版本重新启动。
- **升级**（在线 Daemon）——安装选定的版本，排空并重新启动，然后对结果做健康检查。失败的升级会在可能时回滚。入口是版本过旧的 Daemon 上的 **更新到 \<version\>** 徽标。通道、主机侧升级和回滚见[升级 Daemon](/build-your-team/daemons/upgrade-the-daemon)。
- **重新连接**（离线 Daemon）——签发一个新的一次性令牌，并显示要在该主机上运行的命令。它的身份和 Agent 放置关系都会保留。
- **删除**（离线 Daemon）——移除该 Daemon 并吊销其密钥。它的 Agent 会处于未放置且不活跃的状态，停止响应，直到你把它们放置到另一个 Daemon 上。机器上的本地进程和文件会一直保留，直到你在那台机器上停止或删除它们。

## 放置 [#placement]

放置在你所连接的 Daemon 上的每个 Agent 都在那一台机器上运行——它拥有该 Agent 的工作区、Runtime 进程和会话记录。当两端都在线、就绪，并且与 Agent 的 Runtime、模型和 MCP 服务器兼容时，你可以在 Agent 的**配置**标签页中移动它。要让 Agent 在一台机器宕机时继续存活，请改为把它放置到 [Daemon 组](/build-your-team/daemons/daemon-groups)上。

移动会按已保存的 Agent 定义冷重建 Agent；它不会迁移 Daemon 本地的工作区、记忆或会话记录数据。请先提交或备份本地工作，并预期 GitHub 工作区会在目标机器上重新克隆。

## AgentConnect Cloud [#agentconnect-cloud]

在 [AgentConnect Cloud](https://app.agentconnect.md) 上，Daemon 选择器会多出一项不属于你机器的条目：**AgentConnect Cloud**。把 Agent 放置在那里，它就会在由 AgentConnect 管理的基础设施上运行——不需要准备机器，不需要安装或登录 Runtime，也不需要提供方的 API 密钥。模型访问已包含在内，提供一组精选的 Runtime 和模型，每个 Agent 都在自己独立隔离的环境中运行。

在**基础设施**页面上，它显示为单独一个 **AgentConnect Cloud** 条目；打开它可以看到放置在那里的 Agent 和最近的额度动态。与你自己连接的机器不同，云端放置不绑定到某一台机器：Agent 的工作区、记忆和会话记录位于其托管环境中，AgentConnect 可能会随时间用不同的算力来承载它。云端放置和你自己的机器可以共存于同一个组织；在两者之间移动 Agent 与其他移动一样是冷重建——Agent 会按已保存的定义重新创建，现有的工作区、记忆和会话记录内容不会随之迁移。

### 定价 [#pricing]

云端按用量计费。把 Agent 放置在那里本身不产生费用——你只为其会话的模型用量付费：

- **模型用量按模型提供方公布的 API 价格计费**——与直接调用提供方的 API 相同，没有加价。当提供方调整公布的价格时，云端价格也随之变化。
- **用量从你组织的预付额度余额中扣除**。所有者可在**账单**页面添加额度。余额、账目明细及其背后的分析视图见[账单与用量](/operate-govern/billing-and-usage)。
- **额度耗尽会暂停云端工作**。余额用完后，云端放置的 Agent 会停止接收新的模型流量，直到添加额度为止。没有超额计费。

放置在你自己连接的 Daemon 上的 Agent 从不计费：它们使用那些机器上配置的提供方凭证，其模型流量直接在你的机器和提供方之间传输。

## 会话保留 [#session-retention]

每个 Daemon 都有一个**过期会话**设置：选择一个常用的时间窗口、输入自定义天数，或者无限期保留会话。它控制该 Daemon 保留已完成的会话记录和会话工作树的时长。内容过期后，控制平面仍会保留会话元数据。过期后仍可见的内容见[会话保留与清理](/operate-govern/sessions#retention-and-cleanup)。

## 故障排查 [#troubleshooting]

- “**添加 Daemon”中一直显示“等待 Daemon…”**——命令很可能在你的终端里失败了。检查 Node 版本是否 ≥ 24.12（`node -v`），以及机器能否通过 HTTPS/WSS 访问你的控制平面 URL。
- **Daemon 显示离线但进程仍在运行**——查看日志（`npx -y @agentconnect.md/cli status` 会打印日志路径，默认是 `~/.agentconnect/logs/daemon.log`）。反复出现 `connect/handshake failed` 通常意味着密钥已被吊销——对该 Daemon 使用**重新连接**；如果它已被删除，则重新接入一台新的。
- **选择器中缺少某个 Runtime**——检查 Daemon 用户的 Runtime 安装和已保存的登录。对于 microsandbox，Runtime 还必须安装在所选镜像中。使用 Runtime 卡片中的**主机**、**沙箱**和**虚拟机**标签页检查每种策略；无法运行的策略会在其 Runtime 列表的位置显示原因。
- **某个执行策略不可用**——在 Agent 的**执行策略**选择器中把鼠标悬停在它上面查看原因，并检查 Daemon 日志。SRT 需要其主机工具和用户命名空间；microsandbox 需要 KVM 和 vsock 访问权限。在 Daemon 的 `sandbox` 配置中设为 `false` 的策略会在此 Daemon 上显示为已关闭。见[沙箱隔离](/operate-govern/sandboxing#configure-the-daemon)。
