知识库为你的 Agent 团队提供一个经过评审的共享事实来源，而无需把整个库复制到每个提示词中。用它来存放长期有效的运维手册、架构决策、产品事实和团队实践。同一页面还在单独的卡片中承载组织级的外部记忆连接；每个 Agent 仍然自行选择自己的[记忆后端和策略](/build-your-team/agents/configure-an-agent#memory)。

<Image src={imgKnowledge} alt="发布经过评审的组织知识" width={680} />

在控制台中打开**知识库**。它的两个标签页把已发布内容与提案队列分开：

- **组织**包含已发布、带修订版本的 Markdown，Agent 可以搜索。
- **建议**是组织所有者评审由 Dreaming 提出的知识库和托管技能候选项的地方。

**外部记忆**卡片显示在标签页内容下方，包含 Agent 可以使用的已批准记忆服务和账号连接。

所有组织成员都可以阅读已发布的知识库内容并查看已配置连接的元数据。只有所有者可以发布或修订条目、归档或恢复它们、评审建议，以及管理外部记忆连接。

## 发布知识 [#publish-knowledge]

1. 打开**知识库 → 组织**。
2. 选择**发布知识**，添加标题、Markdown 内容，以及可选的摘要和标签。
3. 发布该条目。

编辑条目会发布一个新的不可变修订版本，而不是覆盖它的历史。当 Agent 不应再找到某个条目时，将其归档；归档的内容之后仍可查看或恢复。

## 评审 Dream 建议 [#review-dream-suggestions]

[Dreaming](/build-your-team/agents/configure-an-agent#dreaming) 可以把 Agent 近期工作中反复出现的模式转化为一条知识库条目或托管技能的提案。提案永远不会自行发布：

1. 以组织所有者身份打开**知识库 → 建议**。
2. 检查提案的 Markdown 或完整的技能文件树及其来源会话。
3. **接受**它以创建一个已批准的不可变修订版本，或者**拒绝**它并把该决定保留在评审历史中。

如果来源 Daemon 离线，建议仍会保留在列表中，但其内容暂时不可用。一旦接受，发布的知识库条目或托管技能就会对组织可用。

被接受的知识库建议会出现在知识库中。被接受的托管技能会出现在**工具与技能 → 技能库**中，并且仍然必须[为每个 Agent 明确启用](/build-your-team/tools-and-skills#enable-tools-and-skills-for-an-agent)。

## 管理外部记忆连接 [#manage-external-memory-connections]

打开**知识库 → 外部记忆**，为组织注册和管理已批准的记忆服务。所有者选择一个经过评审的插件安装，提供所需的凭证和配置，然后创建连接。密钥值在保存后是只写的。

创建连接不会自动改变任何 Agent。打开 Agent 的**记忆**标签页，选择**外部**，选中该连接，并配置它的召回和捕获策略。连接提供可信的服务和凭证；Agent 绑定提供 Agent 范围的身份和策略。

完整的部署、连接、绑定和召回测试，请参照[使用 Mem0 OSS 作为外部记忆的指南](/how-to-guides/external-memory)。

## Agent 如何使用知识库 [#how-agents-use-knowledge]

当任务需要共享上下文时，Agent 会按文本和标签搜索已发布的知识库内容。AgentConnect 不会把整个库注入每个会话，Agent 也不能自行发布或批准条目。

## Dreaming [#dreaming]

Dreaming 通过**托管**记忆进行配置。打开 Agent 的**记忆**标签页可以运行一次 Dream、调整它的运行计划、查看已完成的记忆结果，或者可选地从重复的流程中挖掘可复用的技能。组织所有者仍然在**知识库 → 建议**下评审每一条共享的知识库或托管技能提案。
