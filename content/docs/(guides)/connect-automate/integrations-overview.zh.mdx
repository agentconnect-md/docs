**集成**把一个 Agent 绑定到某个平台或事件源。支持的平台如下：

| 平台 | Agent 响应的内容 | 接入方式 |
| --- | --- | --- |
| [Slack](/connect-automate/chat-platforms/slack) | 频道、话题和私信 | 添加到 Slack，或连接自己的 Slack App |
| [Microsoft Teams](/connect-automate/chat-platforms/msteams) | 一对一聊天、群聊和团队频道 | 管理员通过 Microsoft 登录连接，或注册自己的机器人 |
| [Google Chat](/connect-automate/chat-platforms/googlechat) | 空间中的 @ 提及和私信 | 创建 Chat 应用，连接其服务账号的 JSON 密钥 |
| [Discord](/connect-automate/chat-platforms/discord) | 频道、话题和私信 | 机器人令牌（AgentConnect 会生成邀请链接） |
| [Telegram](/connect-automate/chat-platforms/telegram) | 私信和群组消息 | 来自 @BotFather 的机器人令牌 |
| [Lark / 飞书](/connect-automate/chat-platforms/lark-feishu) | 群组消息和一对一聊天 | 一键应用配置，或 App ID 和密钥 |
| [钉钉](/connect-automate/chat-platforms/dingtalk) | 私信和群组 @ 提及 | 企业内部应用的 Client ID 和 Client Secret（国内版或国际版） |
| [企业微信](/connect-automate/chat-platforms/wecom) | 单聊和群组 @ 提及 | 智能机器人的 Bot ID 和 Secret |
| [微信](/connect-automate/chat-platforms/wechat) | 你自己与 Agent 的一对一聊天 | 用个人微信扫描二维码 |
| [QQ](/connect-automate/chat-platforms/qq) | 私聊和群组 @ 提及 | 官方机器人的 AppID 和 AppSecret（仅限自托管） |
| [GitHub](/connect-automate/triggers-automation/github) | Issue、PR、评论、部署和发布事件 | 安装 GitHub App，并授权 Agent 使用仓库 |
| [GitLab](/connect-automate/triggers-automation/gitlab) | Issue、Merge Request、评论和发布事件 | 通过 OAuth 连接（AgentConnect 为各 Agent 创建服务账号） |
| [Azure DevOps](/connect-automate/triggers-automation/azure-devops) | Azure Repos 中的 PR 和评论 | 通过 Microsoft 登录连接，或使用自己的应用 |
| [Gitea / Forgejo](/connect-automate/triggers-automation/gitea) | Issue、PR、评论和评审 | 每个组织连接一个专用机器人用户的令牌 |
| [Linear](/connect-automate/triggers-automation/linear) | 委派的 Issue 和 @ 提及 | 在 Linear 中授权工作区 |
| [Webhook](/connect-automate/triggers-automation/webhooks) | 外部系统的 JSON 事件 | 创建 Webhook，将请求发送到生成的端点 |

可以在 Agent 页面（**集成 → 添加集成**）或 Agent 列表中添加集成。

## 机器人是身份，集成是绑定 [#bots-are-identities-integrations-are-bindings]

在聊天平台上，**机器人**是存在于你的 Slack 工作区、Telegram 群组、Discord 服务器或 Lark / 飞书租户里的独立身份，带有自己的令牌。集成把这个机器人绑定到某一个 Agent。

- 删除集成会**释放机器人**，而不会删除它。你可以随后在**使用已有机器人**选择器里，把它复用给另一个 Agent。
- 机器人在**集成 → 消息应用**中按组织统一管理，详见[机器人](/connect-automate/chat-platforms/bots)。

可见哪些平台选项取决于 Agent 所在 Daemon 的能力和部署设置。**QQ 仅限自托管。** 具体前提条件和自托管配置请查看各平台指南。

## 绑定频道 [#binding-channels]

不需要提前选择频道：**把机器人邀请进频道，它就会自动出现在 AgentConnect 中。** 在 Agent 的集成卡片上打开频道设置，先选择**会话模式**。

### 会话模式 [#session-mode]

**会话模式**决定 Agent 在对话中如何组织工作：

- **自动**：协调会话会读取频道主聊天中的消息，以及还没有归属任务的话题消息。它可以把请求转给正在处理同一主题的已有任务、在消息所在话题中开启新任务、直接回答简单问题，或者不回复。凡是 @ 提及 Agent 的消息都会被处理；如果协调会话无法处理，系统会自动为它开启一个任务。之后，成员可以直接在任务话题里与该任务交流。协调会话判断期间，支持表情回应的平台会显示 🤔。
- **按话题**：每条符合触发条件的主聊天消息都会开启一个独立会话，话题内的回复延续该会话。
- **单一会话**：对话中所有符合触发条件的消息，无论在主聊天还是话题中，都进入同一个连续会话。发送 `!new` 可以开始新会话。

自动模式下由协调会话决定哪些消息需要回复，因此**触发条件**会被隐藏，菜单底部仍保留**关闭**选项。自动模式不能与**按决策**或共享机器人的**或按决策选择**同时使用，如需使用决策，请先把该行切换为**按话题**。

在任务话题中，`!new` 会重启该任务，`!stop` 会暂停它，直到有人再次在话题中提及该 Agent。在对话主聊天中，`!new` 会启动新的协调会话，但保留已开启的任务继续运行；`!stop` 会停止协调会话当前的一轮执行。在[会话](/operate-govern/sessions)中打开协调会话，可以在**任务**标签页查看它管理的所有任务以及各自的进度摘要。

自托管 Daemon 默认启用自动模式，除非 `config.json` 中配置了 `"features": { "autoSessionMode": false }`。关闭该开关后，Daemon 会按**按话题**模式处理自动模式的对话。

### 触发条件：按话题和单一会话 [#respond-to-per-thread-and-single-session]

选择**按话题**或**单一会话**后，通过**触发条件**指定哪些消息可以激活 Agent。可选范围取决于具体平台：

- **@ 提及**：被提及时回复。在 Agent 已加入的话题（thread）中，未提及的后续消息也会继续处理。
- **所有消息**：频道里的每条消息都会触发该频道的 Agent。

点击频道行上的 **+ 决策**，可以用[决策](/build-your-team/decisions#respond-in-a-channel)筛选消息，只在判断结果符合规则时回复。生效中的规则会显示为**按决策**，点击旁边的 × 即可移除并恢复为常规频道设置。

[Linear](/connect-automate/triggers-automation/linear) 的配置方式相同，只不过对应的对话单位是工作区里的**团队**，连接后会自动列出。因为每个 Linear 事件本身就是发给该应用的，团队行只提供 **@ 提及**、**按决策**和**关闭**。

### 关闭对话 [#turn-off-a-conversation]

**关闭**单独位于菜单底部。开启后会停止响应该频道里的所有入站消息，包括提及、已有话题的延续、控制命令以及共享机器人的回退路由。菜单收起时，按钮会显示当前设置（例如**自动**或**按话题 · @ 提及**），禁用时则显示**关闭**。重新选择一种会话模式即可恢复对话。

关闭对话会让机器人留在频道中并保留历史会话，只是静音入站触发。定时任务或其他 Agent 发起的主动交接仍可以向该频道发消息。如果需要把机器人移出频道或服务器，请在聊天平台侧管理成员身份。

### 新频道默认 [#new-channel-defaults]

Agent 集成卡片底部的**新频道默认**决定新发现的频道和群组对话的初始状态：

- **自动**：当平台和 Daemon 都支持时的默认值；不支持时则回退为**按话题**加 **@ 提及**。
- **@ 提及 · 按话题**：每个话题使用独立会话，通过提及触发。
- **关闭**：保持静音，等待有编辑权限的成员手动启用。

修改该默认值不会影响已有对话和一对一私信。受限 Agent 的对话以及平台标记为外部的对话，仍会默认保持关闭。助手模式下，支持的对话在自动模式可用时固定使用协调会话，否则固定为单一会话；这会覆盖常规的会话模式设置，但保留关闭状态。

### 私信 [#direct-messages]

有人给机器人发消息后，私信就会自动出现，每个 Agent 各自管理自己的私信对话。一对一私信通过**开启 / 关闭**控制是否响应。Slack 额外支持**按话题**和**单一会话**（助手模式下，支持自动模式时 Slack 私信会使用协调会话）。Telegram、Discord 和 Lark / 飞书的一对一私信始终是一个连续会话。群组对话支持与该平台频道相同的会话模式，Slack 群组私信支持全部三种。受限 Agent 的对话初始为关闭，需由有权限的编辑者手动开启。

### 共享机器人 [#shared-bots]

通常是一个机器人绑定一个 Agent。**共享 Slack 机器人**可以让一个机器人身份服务多个 Agent，而已连接的 **Linear 工作区**始终如此，上面启用的所有 Agent 共用部署中唯一的 Linear 应用。在**集成 → 消息应用**中展开机器人，为每个频道指定**默认分发** Agent，就可以在 Slack 中只暴露一个“@Assistant”，背后按频道交由不同专家 Agent 处理。如果想按具体对话内容分配，可以使用**或按决策选择**，配合[决策](/build-your-team/decisions#route-a-shared-bot)路由。

频道触发条件作用于共享机器人。把它切换为**关闭**后，该频道中经由这个机器人的路由就会停止。

### 受限 Agent [#restricted-agents]

当 Agent 的团队可见范围设为**指定成员**时，它的聊天对话同样受限。新发现的频道和私信初始都为**关闭**，必须由有权限的编辑者在集成卡片上逐一开启。任意 Agent 之后也都可以手动切回关闭以显式静音。参见[团队可见范围](/operate-govern/permissions-overview/team-visibility#what-a-restricted-agent-changes)。

## 在其他对话中读取和发消息 [#reading-and-posting-in-other-conversations]

当有人让 Agent 在当前对话之外的另一个对话中读取内容或发送消息时，Agent 会代表这个人执行操作，权限不会超出这个人本身。它正在回复的当前对话始终对它开放。

只有在提问者本人可以查看的目标对话里，Agent 才能读取消息、话题、表情回应或书签：

- 公开频道：提问者是该工作区的正式成员，而非访客。
- 提问者所在的私密频道或群组私信。
- 提问者自己与 Agent 的私信。其他人的私信永远不可读取。

只有在提问者自己能发言的位置，Agent 才能发消息、添加表情回应、安排定时消息、发起对话，或修改书签、画布和列表。以下三种场景还有额外规则：

- **私信**：只能发送给你所在组织的成员（在 Slack 上必须是工作区正式成员，不能是访客）。
- **与其他组织共享的对话**（如 Slack Connect 频道）：来自其他对话的消息会先生成草稿。你所在组织的成员（通常是提问者）会在 Slack 私信中收到一张确认卡片，选择 **Approve** 或 **Discard**。超过 24 小时未处理的草稿会自动过期。
- **非人工发起的运行**（如 Webhook、GitHub 事件或另一个 Agent 的请求）：只能读取公开频道和它所在的对话，也只能在自己所在的对话里发消息。定时任务代表最后编辑它的人；如果从未被编辑过，则代表创建者。

当 Agent 引用私密对话里的内容时，会说明来源。如果请求被拒绝，它只会说明无法分享该内容或无法发到那里，不会透露目标对话是否存在。

Slack 和 Lark / 飞书会提供对话成员信息。Telegram 和 Discord 不提供，因此在这两个平台上，只有平台标记为公开的群组或频道才算数：带有公开 @用户名 的 Telegram 群组，或服务器内所有人可见的 Discord 频道。

### 跨平台交接 [#cross-platform-handoffs]

把同一个 Agent 连接到多个聊天平台后，它可以在不同对话之间主动交接任务。请仅在你信任并已批准互通信息的工作区之间使用此功能。目标端会开启一条关联的新会话，而不会合并两边的聊天记录。

在另一个平台（或经由该 Agent 的另一个机器人）执行读写操作前，AgentConnect 必须先通过提问者在**个人资料 → 登录方式**中关联的聊天账号，确认对方是你所在组织的成员。随后，目标端的访问权限按两条规则判定：

- **已关联目标工作区账号**：Agent 按提问者在该工作区关联的聊天账号检查权限。公开频道要求是正式成员，私密频道或群组私信要求是其中的成员。
- **未关联目标工作区账号**：如果提问者没有关联该工作区的账号，Agent 只能在提问者可以在**会话**中打开的对话里读取或发消息。Telegram 和 Discord 账号无法关联，因此在这两个平台上始终适用这条规则。

在 AgentConnect Cloud 上，可以关联 Slack 账号。因此你可以从 Slack 交接到 Telegram、Discord 或 Lark / 飞书里 Agent 已有且你有权打开的会话。但无法从 Telegram 或 Discord 反向交接到 Slack 或 Lark / 飞书，因为 AgentConnect 无法识别那边的用户身份，他们只能访问同一个机器人所在的其他频道和群组。自托管部署还可以关联 Lark 和飞书账号。参见[在受信任的工作区之间交接对话](/how-to-guides/hand-off-conversations-across-messaging-platforms)。

## 对话内命令 [#in-conversation-commands]

这些命令可以直接控制当前对话，无需通过模型处理。由于 Slack 把 `/` 命令保留给了应用，Slack 上改用 `!` 前缀。

| 操作                       | 其他平台                            | Slack                      |
| -------------------------- | ----------------------------------- | -------------------------- |
| 停止并静音                 | `/stop`                             | `!stop`                    |
| 取消当前轮次               | `/cancel`                           | `!cancel`                  |
| 恢复                       | `/resume`                           | `!resume`                  |
| 排队一条消息               | `/queue <message>`                  | `!queue <message>`         |
| 查看会话状态               | `/status`                           | `!status`                  |
| 更改模型、推理强度或权限   | `/models`、`/effort`、`/permission` | 相同的命令，改用 `!`       |
| 切换快速模式               | `/fast on`、`/fast off`             | `!fast on`、`!fast off`    |

在按话题模式和自动模式的任务话题中，**停止**同时会将该话题静音，直到有人再次提及 Agent 或发送**恢复**。在单一会话模式和自动模式的主聊天中，**停止**只会中断当前轮次，不会静音对话（如需静音请设为**关闭**）。**取消**只中断当前轮次。

运行时设置命令（`/models`、`/effort`、`/permission`、`/fast`）只有在 Agent 的[**聊天中可以做什么**](/build-your-team/agents/configure-an-agent#what-people-can-do-in-chat)设为**对话、批准并修改设置**时才生效。在开启**遵循 Slack 访问权限**的 Slack 上，只有 Agent 的编辑者能执行这些命令，其他人会收到私信提示，说明哪些人有权修改。在 Telegram 和 Discord 上，这些命令会出现在原生命令菜单中，注册名称为 `/models` 而非 `/model`（手动输入两者均可）。

当工具调用需要批准时，Slack、Telegram、Discord、Lark / 飞书和 Google Chat 会在对话中发送审批卡片，除非 Agent 设为**和 agent 对话**。谁可以操作这张卡片同样由该设置决定，参见[当运行请求权限时](/operate-govern/sessions#when-a-run-asks-for-permission)。

## Agent 应该有多“健谈”？ [#how-chatty-should-an-agent-be]

Agent 的**输出模式**控制同步到聊天平台的内容详略程度：

- **极简**：只保留一条实时更新的回复。
- **低**：仅发布回复。
- **中**：额外显示工具调用和计划。
- **高**：再包含推理过程和工具输出。
- **无**：仅在 Web 会话中保留输出。

完整的会话记录始终可以在[会话](/operate-govern/sessions)中查看。
