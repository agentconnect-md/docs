AgentConnect 提供托管的 **MCP 服务器**，地址为：

```
https://mcp.agentconnect.md
```

将其接入 Claude（或任意支持 streamable HTTP 的 MCP 客户端）后，你的助手可以直接查看和管理组织内的资源：

> _“我们现在有哪些 Agent 在线？”_
> _“这周 Token 花了多少，按 Agent 怎么分布？”_
> _“每晚的报告定时任务跑了吗，结果成功吗？”_
> _“为评审 Agent 创建一个工作日定时任务。”_

在 AgentConnect 内部则无需额外配置：在单 Agent 的 [Playground](/build-your-team/agents/playground#configure-agentconnect-from-a-conversation) 对话中，Agent 默认就可以使用同一套工具，每项修改都会在控制台中等待你确认。

## 从 Claude 连接 [#connect-from-claude]

**Claude（claude.ai / 桌面版）**：进入设置 → **连接器** → **添加自定义连接器**，填入 `https://mcp.agentconnect.md`，并在浏览器中完成授权流程：使用已启用的方式登录，**选择要绑定的组织**，确认客户端请求的读写权限后点击**授权**。整个过程采用标准的 OAuth 2.1 与动态客户端注册，无需手动复制密钥。

**Claude Code**：

```bash
claude mcp add --transport http agentconnect https://mcp.agentconnect.md
```

运行后按提示在浏览器中完成登录授权（`/mcp` → 认证）。在 CI、服务器等无头环境中，可以跳过 OAuth，改用 [API 密钥](/api)：

```bash
claude mcp add --transport http agentconnect https://mcp.agentconnect.md \
  --header "Authorization: Bearer $AGENTCONNECT_API_KEY"
```

其他 MCP 客户端的接入方式相同：支持授权码流程就走 OAuth，否则在 `Authorization: Bearer` 请求头中传入个人 API 密钥。

## 读取工具 [#read-tools]

获得 `mcp:read` 权限后，助手可以查询以下信息：

| 领域     | 工具                                                             |
| -------- | ---------------------------------------------------------------- |
| 身份     | `whoami`                                                         |
| Agent    | `listAgents`、`getAgent`                                         |
| Daemon   | `listDaemons`、`getDaemon`、`listDaemonCapabilities`             |
| 工作区   | `listWorkspaceFiles`、`readWorkspaceFile`                        |
| 定时任务 | `listCrons`、`getCron`、`listCronRuns`                           |
| 会话     | `listSessions`、`getSession`                                     |
| 分析     | `getUsage`                                                       |
| 集成     | `listIntegrations`、`listBots`、`listAgentHooks`、`listHookRuns` |
| 代码托管 | `listGithubInstallations`、`listGithubRepositories`、`getGithubRepositoryAccess`、`listGitlabConnections`、`listGitlabBots`、`listGitlabProjects`、`listGiteaConnections`、`listGiteaRepositories` |
| 决策     | `listDecisions`、`getDecision`、`listDecisionProviders`、`getBotDecisionRouting`、`getCodeHostDecisionRouting`、`listDecisionEvaluations` |
| 成员     | `listMembers`                                                    |

`whoami` 返回当前登录身份、所属组织与角色。会话工具只返回状态、用量和链接，不返回会话正文。`listBots` 仅返回元数据，不包含令牌内容；`getUsage` 返回总用量和各 Agent 的明细。`getDaemon` 会列出每个 Runtime 的可用模型及其支持的推理强度和权限模式。工作区工具直接从 Agent 所在的 Daemon 实时读取文件。完整会话记录始终保存在[你的 Daemon 上](/getting-started/how-it-works)。

## 写入工具 [#write-tools]

当客户端请求并经你批准 `mcp:write` 后，还可以执行以下修改：

| 领域     | 工具                                       |
| -------- | ------------------------------------------ |
| Agent    | `createAgent`、`updateAgent`、`setAgentWorkspace`、`deleteAgent` |
| Daemon   | `renameDaemon`                             |
| 定时任务 | `upsertCron`、`runCron`、`deleteCron`      |
| 集成     | `setChannelTrigger`、`createGithubTrigger`、`removeIntegration` |
| 决策     | `createDecision`、`updateDecision`、`deleteDecision`、`saveBotDecisionRouting`、`saveCodeHostDecisionRouting`、`deleteCodeHostDecisionRouting`、`previewDecision`、`previewIntegrationChannelDecision`、`previewBotDecisionRouting` |

写入接口的范围有意比控制台和 REST API 更收敛，不涉及凭证、成员、组织设置、访问控制列表和机器人密钥。

`deleteAgent`、`setAgentWorkspace`、`deleteCron`、`removeIntegration`、`deleteDecision` 和 `deleteCodeHostDecisionRouting` 属于破坏性操作，其中 `setAgentWorkspace` 可能会丢弃该 Agent 在 Daemon 上的代码检出（包含未提交的改动）。除客户端自带的审批弹窗外，这些操作还要求提供与线上值完全匹配的确认字段（两个 Agent 工具填 Agent 名称，其余依次为集成或决策名称、定时任务名称/ID，或仓库的 `owner/repo`）。确认值缺失或不匹配时，请求会被拒绝。

## 控制台对话框 [#console-dialogs]

部分配置需要填写凭证或在浏览器中进行交互选择。以下工具不会直接修改数据，而是打开对应的控制台对话框：

| 对话框 | 工具 |
| --- | --- |
| 添加或编辑集成 | `configureIntegration` |
| GitHub、GitLab 和 Gitea 连接 | `manageCodeHosts` |
| Agent 的编辑器 | `configureAgent` |
| Agent 的工具与技能 | `manageAgentTools` |
| 安装技能 | `installSkill` |
| 添加 MCP 服务器 | `installMcpServer` |

在单 Agent 的 [Playground 对话](/build-your-team/agents/playground#configure-agentconnect-from-a-conversation)中，对话框会直接在控制台里打开，并尽量预填已有信息，方便你直接完成。其他客户端则会展示一个页面，引导你前往控制台操作。

## 权限与信任 [#permissions--trust]

- 每个连接**以你的身份作用于单个组织**，即授权时选中的组织（或 API 密钥所属的组织）。如需操作其他组织，请另行建立连接。
- OAuth 权限按作用域严格隔离：`mcp:read` 仅开放读取工具，写入工具需要 `mcp:write`。个人 API 密钥则遵循其权限级别：[完全访问](/api#create-a-key)密钥具备你角色的全部权限，[只读](/api#create-a-key)密钥只能调用读取工具，[Agent 对话](/api#create-a-key)密钥无法使用连接器。
- 你的**角色权限与资源可见范围完全一致**。这些工具底层调用的就是控制台同款 REST 接口，因此查看者的连接器无法越权查看或修改内容，[受限资源](/operate-govern/permissions-overview/team-visibility)也会继续隐藏。
- 不再希望某个客户端代表你操作时，直接撤销对应的 OAuth 连接或个人 API 密钥即可。
