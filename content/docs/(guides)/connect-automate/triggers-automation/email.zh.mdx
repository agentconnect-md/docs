Email 集成会给 Agent 一个**自己的邮箱地址**。给这个地址写信或转发邮件，Agent 就会处理并在同一个线程里回信。在任何对话里让它给某人发邮件，它也会用这个地址发出一封新邮件。

## 添加地址 [#add-an-address]

在 Agent 页面中打开**集成 → 添加集成 → Email**，取一个名字。地址就是这个名字加上你所在工作区的邮件域名，例如 `support-bot@mail.example.test`。输入框旁会实时提示这个名字能不能用。

- 名字长 3 到 40 个字符，只能用小写字母、数字、`.` 和 `-`。
- `admin`、`billing`、`security` 这类容易被当成官方身份的名字不能用。
- 地址不会被重复使用。删除集成后，这个地址就永久停用，之后寄来的邮件不会落到别人手里。

Agent 的**集成**卡片上会显示地址和复制按钮，还有一行说明谁能给它写信。

## 设置谁能写信 [#who-can-write]

点击地址旁的设置按钮，打开 **Email settings**。

**接收来信（Accept mail from）**

- **组织成员**（默认）：只接收成员登录用的邮箱发来的信。成员账号关联的每一种登录方式的邮箱都算，比如工作和个人两个 Google 账号。Microsoft 工作或学校账号的邮箱，只有在它的域名已被你的组织验证时才算。其他人的来信会被拒收，对方的邮件服务器会告诉他被退信了。
- **任何人**：接收任何人的来信。成员发来的信仍然按成员处理。

不管选哪一项，来信都要通过发件人域名的校验，冒用别人地址的信会被拒收。自动邮件（比如休假自动回复、邮件列表）会被忽略，避免两个自动回复互相回个不停。

**组织外来信谁能看到（Who sees mail from outside the organization）**

选了**任何人**之后，可以决定组织外的人来信所开的对话，在 console 里谁能看到：

- **能编辑这个 Agent 的人**（默认）：按当下的编辑者算。编辑者有变动，能看到这些对话的人也跟着变。
- **组织里所有人**。
- **指定一位成员**。

成员自己来信开的对话，只有他本人能看到。

## 对话和回信 [#conversations]

每个邮件线程对应一个会话，可以在[会话](/operate-govern/sessions)里看到。线程里的后续来信会接着这个会话，Agent 也能读到这个线程之前的邮件。

Agent 每一轮只回一封信，以回复的形式发在同一个线程里：收件人是来信的人，并抄送线程里的其他成员。选了**任何人**时，在这个线程里自己写过信的组织外地址也会被抄送；只是被别人列进 Cc 的地址不会。哪些人没被抄送，Agent 会知道，可以在回信里说明。

附件暂时不会交给 Agent，它只能看到附件的文件名。

## 让 Agent 发邮件 [#send-mail]

在任何和 Agent 的对话里（console、聊天平台或邮件线程），直接让它发邮件：

> 把发布说明发到 ops@example.test，抄送 dana@example.test。

Agent 会用自己的地址发出一封新邮件。对方回信后，会在这封邮件自己的线程里接着进行，会话从 Agent 发出的那封信开始。

- 如果是组织成员在自己的消息里提的要求，Agent 可以发给任何地址。
- 如果要求来自共享对话里的访客、定时任务或 webhook 的运行，或者是委派出去的任务，Agent 只能发给组织成员。
- 一封邮件最多 50 个收件人。

发信不需要任何人审批，因为提要求的成员就是本来要审批的人。需要注意的是，Agent 读到的内容（网页、文件、来信）可能会诱导它把知道的东西发出去。如果这个风险对某个 Agent 不可接受，就不要给它邮箱地址。

## 限制 [#limits]

| | |
| --- | --- |
| 新线程 | 每个发件人每小时最多在一个 Agent 上发起 30 次。 |
| 回信 | 每个地址每天最多 200 封。 |
| 发给组织外的人 | 每个地址每天最多 100 个收件人，回信和新邮件合计。 |
| 每封邮件的收件人 | 50 个 |

发不出去的回信会留在会话里，标记为未送达，并写明原因。
