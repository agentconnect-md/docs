通过 Azure DevOps 集成，Agent 可以直接在 **Azure Repos** 中工作。你可以把 Git 仓库设为 Agent 的工作区或附加仓库，也可以让 Agent **监视仓库**，由 Pull Request 和评论自动开启会话。Agent 会在 Pull Request 的评论线程中回复，支持提交带投票的正式评审，并将运行状态写入 Pull Request 状态。

此集成支持 **Azure DevOps Services**（`dev.azure.com`），不支持 Azure DevOps Server、TFVC 仓库和 SSH 远程地址。

AgentConnect 在 Azure DevOps 中采用**每个组织一个身份**的模式，即 AgentConnect 应用（在你的 Microsoft Entra 租户中对应一个服务主体）。所有 Agent 的操作（克隆、推送、评论、评审和上报状态）都会归属于该应用。

## 开始之前 [#before-you-start]

你需要一个 **Microsoft 工作或学校账户**，且该账户必须是目标 Azure DevOps 组织的 **Project Collection Administrator**，同时是该组织所属 Microsoft Entra 租户的成员或来宾。个人 Microsoft 账户无法连接。

## 连接 Azure DevOps [#connect-azure-devops]

每个组织只需在**集成 → 代码托管平台 → Azure DevOps → 使用 Microsoft 连接**中连接一次。

1. 使用上述管理员账户**登录**。如果租户开启了管理员审批，需要先由 Microsoft Entra 管理员为 AgentConnect 应用授予一次同意，然后再重新登录。
2. **选择组织**：AgentConnect 会列出你所属的 Azure DevOps 组织。如果目标组织位于你当前登录之外的其他租户，系统会引导你切换到对应租户登录。
3. **选择项目**：勾选需要让 Agent 访问的项目。选中的项目默认开启**写**和**允许触发器**：

   | 选项           | 授予应用的权限                                            |
   | -------------- | --------------------------------------------------------- |
   | **读**         | Agent 可以克隆和读取代码，但不能推送（项目的 Readers）。  |
   | **写**         | 还可以推送代码和创建 Pull Request（Contributors）。       |
   | **允许触发器** | Pull Request 可以启动 Agent（项目的 Service Hook 权限）。 |

   勾选**所有项目**会把相同的权限配置应用到当前以及未来新建的全部项目，后续新增项目无需再次配置。只有 Project Collection Administrator 可以开启此选项。

<Image src={imgProjectAccess} alt="选择项目：未勾选所有项目，Example Project 开启写与允许触发器，Example Docs 仅为只读" width={480} />

随后，AgentConnect 会以 **Basic** 访问级别把应用添加到组织（占用一个付费许可证），将其加入你指定的权限组，并验证应用可以访问对应仓库。

请只授予 Agent 确实需要的项目。该应用能够访问其所属权限组允许的一切资源，且令牌在整个组织内有效；每个 Agent 只能操作自己被授权仓库的边界，由 AgentConnect 在 Daemon 侧强制控制（见[访问由 Daemon 控制](#access-is-enforced-by-the-daemon)）。

如果操作者只是 **Project Administrator** 而不是 Project Collection Administrator，就无法以 Basic 访问级别添加应用。此时 AgentConnect 会显示一份操作清单：由 Project Collection Administrator 前往**组织设置 → 用户**，按客户端 ID 以 Basic 访问级别添加该应用，完成后你就可以回到卡片继续配置。

### 管理项目访问 [#manage-project-access]

点击卡片上的**管理项目访问**会重新执行登录，并展示应用当前的项目权限。保存后，Azure DevOps 中的权限会与页面配置保持一致：取消勾选项目或**所有项目**、改为**读**或取消**允许触发器**，都会收回相应权限。

### 使用自己的应用 [#use-your-own-application]

点击**改用自己的应用**可以连接你在自己租户中注册的应用：填入组织名、租户 ID、客户端 ID 和客户端密码。你需要自行将该应用的服务主体加入组织（Basic）及相应的项目组；如果需要使用触发器，还需为其授予各项目 Service Hook 的**查看订阅**和**编辑订阅**权限。

## 仓库 [#repositories]

仓库会在首次被使用时自动登记到组织中，例如被选为 Agent 的[工作区](/build-your-team/agents/workspaces-and-repos)、添加为附加仓库，或在触发器中被选中。仓库选择器会列出应用有权查看的所有仓库。

每个 Agent 在各个仓库上可以配置**读**或**写**权限。授予写权限要求所属项目具备**写**权限；如果应用对某个仓库没有推送权限，保存该仓库的写权限工作区会被拒绝。

<Image src={imgCodeHosts} alt="Azure DevOps 卡片：已连接的组织、管理项目访问入口以及三个仓库的触发器状态" width={760} />

配置了触发器的仓库会显示最近一次事件的到达时间；需要关注时会展示状态标记：

| 标记             | 处理方式                                       |
| ---------------- | ---------------------------------------------- |
| **触发器待验证** | 无需操作，收到第一个事件后会自动清除。         |
| **未允许触发器** | 在管理项目访问中为该项目开启**允许触发器**。   |

点击仓库行上的钥匙图标可以**轮换** Azure DevOps 签名 Webhook 投递所用的密钥。旧密钥会继续有效 36 小时，确保已排队的事件投递不会失败。

## 访问由 Daemon 控制 [#access-is-enforced-by-the-daemon]

Azure DevOps 无法签发仅限单个仓库或只读权限的令牌，因此**真实令牌永远不会进入 Agent 会话**。Git 和 Azure CLI 会通过 Daemon 的[凭证代理](/operate-govern/sandboxing/credential-protection#code-host-credentials)访问 Azure DevOps，由代理仅针对该 Agent 已授权的仓库注入令牌，并在权限为只读时拦截推送和 API 写操作。

装有 `azure-devops` 扩展的 **Azure CLI** 在会话中可以正常使用（如 `az repos show`、`az repos pr create`、`az repos pr update` 等）。如果你自行运行 Daemon，请在 Agent 的执行环境中提前安装 CLI 及其扩展。可能暴露其他仓库信息的列表命令（例如 `az repos list`，或不带 `--repository` 列出 Pull Request）会被拦截。

Agent 还内置了三个无需 CLI 的工具：`azureDevOpsPullRequest`（创建、编辑、完成、放弃、重新激活 Pull Request 以及管理标签）、`azureDevOpsComment`（评论线程与回复）和 `readAzureDevOpsPullRequest`。由 Agent 创建的 Pull Request 会附上 Agent 署名。

## 监视仓库 [#watch-a-repository]

在 Agent 页面，进入**集成 → 添加集成 → Azure DevOps**。

<Image src={imgAddIntegration} alt="选择了 Azure DevOps 的添加集成对话框：选择仓库、Pull Request 触发时机和评审格式" width={560} />

目标仓库必须已经是该 Agent 的工作区或附加仓库，且所属项目已开启**允许触发器**。选择 Pull Request 触发 Agent 的时机：

- **opened**：Pull Request 创建时触发。
- **any update**：在创建的基础上，还包括新提交、重新打开 Pull Request 以及新评论。
- **@-mention**：仅当 Pull Request 描述或评论中以 `@<agent-name>` 提及该 Agent 时触发。

无论触发时机如何配置，只要将 AgentConnect 应用添加为 Pull Request 的评审者，就会触发一次评审。由于 Azure DevOps 的界面评审者选择器只列出个人用户，添加应用需要通过 REST API 或 `az repos pr reviewer add` 完成。

AgentConnect 会自动创建和维护仓库的 **Service Hook**（按已配置触发器所需的事件类型分别创建），并在最后一个触发器删除时自动清理。多个监视同一仓库的 Agent 共用这些 Service Hook。

<Image src={imgAgentCard} alt="一个 Agent 的 Azure DevOps 卡片，显示一个被监视的仓库及其 Pull Request 触发器" width={640} />

## 谁可以触发 Agent [#who-may-trigger-an-agent]

事件到达时，AgentConnect 会实时查询 Azure DevOps，检查触发者（包括其个人权限和所属各权限组）是否具备该仓库的**贡献（contribute）**权限。无法向仓库推送代码的用户不能启动 Agent。对于评审请求和重新打开的 Pull Request，系统会检查 Pull Request 作者的权限。编辑评论和点赞不会触发任务。

AgentConnect 应用自己发表的评论不会触发 Agent。不过，由应用在同一仓库中创建的 Pull Request 仍会进入评审流程，使一个 Agent 可以评审另一个 Agent 的工作；应用向 Pull Request 推送的提交也会像普通提交一样触发新一轮检查。

## Agent 会做什么 [#what-the-agent-does]

每个符合条件的事件都会在 Agent 所在的 Daemon 上开启一个会话，并出现在[会话](/operate-govern/sessions)列表中，附带跳回 Pull Request 的链接。

- **回复**：在触发本轮任务的评论线程中回复，或在 Pull Request 上发起新线程。任务启动时，AgentConnect 会先为触发评论点赞。
- **评审**：在触发器上配置了评审格式后，新创建的 Pull Request、新提交和评审请求都会触发正式评审，包含每条行内评论对应的独立线程（保留多行范围）、一条汇总线程以及投票结果：批准对应 **Approved**（`10`），要求修改对应 **Waiting for author**（`−5`）。仅发表评论的评审不会改动投票。在评论中提及 Agent 只会在该线程中回复，不会发起正式评审。
- **运行状态**：在 Pull Request 上写入名为 `agentconnect/<agent-name>` 的状态，链接到控制台中的对应会话。只有在管理员将其添加到分支策略的必需状态检查后，该状态才会阻止完成 Pull Request。

如需让 Agent 在同一个 Pull Request 上再次运行，可以在会话中发消息、推送新提交，或再次提及该 Agent。

由于所有 Agent 共用同一个 Azure DevOps 应用身份，它们在同一个 Pull Request 上只共享**一票**，以最近一次提交的评审结果为准。每个 Agent 各自的评审结论仍会保留在对应的汇总线程和 Pull Request 状态中。

## 断开连接 [#disconnect]

点击**断开连接**会先删除 AgentConnect 创建的 Service Hook，再释放连接，Agent 随即停止在这些仓库上响应。如果要从 Azure DevOps 中彻底移除该应用，请前往**组织设置 → 用户**中删除它，并按需在 Microsoft Entra 中删除对应的企业应用。

## 自托管部署 [#self-hosted-deployments]

上述功能在 AgentConnect OSS 上完全一致。运维人员只需配置一次部署级别的 Microsoft 应用，并将控制台的 Azure DevOps 连接页面添加为额外的重定向 URI，详见 [Microsoft Teams 部署应用](/self-hosting/provider-apps#microsoft-teams-deployment-app)。如果未配置部署级应用，各组织也可以直接通过[自己的应用](#use-your-own-application)连接。
