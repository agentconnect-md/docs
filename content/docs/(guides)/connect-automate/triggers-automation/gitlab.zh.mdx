通过 GitLab 集成，你可以让 Agent **监视一个项目**。新的 Issue、Merge Request 和评论会自动开启会话，Agent 也会直接在 Merge Request 中以备注和评审的形式回复。这套机制在 **GitLab.com** 和**自管理实例**上的行为完全一致。同一个部署只能连接其中之一，不能同时连接两者。

GitHub 集成是通过安装在组织上的单个 App 执行操作，而 GitLab 则会为**每个 Agent 分配独立的用户**：在你首次为该 Agent 分配项目时，系统会自动创建一个群组服务账号。该 Agent 在 GitLab 上的所有操作（克隆、推送、评论、评审）都会记在这个账号名下，撤销它也只会影响这一个 Agent。

## 连接 GitLab [#connect-gitlab]

管理员只需在**集成 → 代码托管平台 → 连接 GitLab** 中为部署连接一次。在浏览器完成 OAuth 授权后，该账号就会成为部署的**管理身份**，AgentConnect 用它发现项目、为各 Agent 创建服务账号并管理项目 Webhook。Agent 执行任务时不会使用这个管理身份。

在 GitLab.com 上，请使用项目所在**顶级群组的 Owner** 账号进行连接。创建 Agent 服务账号需要顶级群组 Owner 权限，仅具备项目级 Maintainer 权限是不够的。在 AgentConnect OSS 上，运维人员需要先[配置部署的 GitLab OAuth 应用](/self-hosting/provider-apps#gitlab)。该文档也说明了自管理实例的前置条件，以及在自管理实例上配置创建权限的两种方式。

连接按组织维度隔离，一个部署只对接一个 GitLab 实例。一旦产生 GitLab 相关数据，实例地址就不能再更改。已保存的连接、令牌和数字项目 ID 本身不包含实例标识，修改地址会导致把原实例的凭证发往另一个实例。

## 为 Agent 分配项目 [#give-an-agent-a-project]

不需要单独执行“安装到此项目”的步骤。当你首次把某个项目分配给 Agent（作为[工作区](/build-your-team/agents/workspaces-and-repos)或已授权的其他仓库）时，系统会自动完成配置，具体包括三件事：

1. 如果该 Agent 在项目所属顶级群组中还没有**服务账号**，自动创建一个。
2. 将该服务账号以 **Developer** 角色加入项目。
3. 配置用于向 AgentConnect 推送事件的项目 **Webhook**。

项目必须位于**群组**中。个人命名空间下的项目无法配置，因为 GitLab 的服务账号归属于群组。如果尝试配置个人命名空间项目，AgentConnect 会返回 `personal_namespace_unsupported`，不会创建任何资源。

在**集成 → 代码托管平台**中，GitLab 卡片会列出所有 Agent 及其对应的服务账号。需要处理的项目会聚合在 **_N_ 个项目需要关注**标记下，展开即可查看并操作。每一行项目提供三个操作：

- **修复**：重新执行上述初始化步骤。当有人手动删除了机器人账号或 Webhook 时可以使用。
- **移除**：删除项目 Webhook 和对应的机器人账号，让 Agent 停止在该项目响应。项目的代码和 Git 历史不受影响。
- **接管管理权限**：将项目的管理权转移到你当前的连接上。当最初配置该项目的连接已经断开，或者原账号持有人离职时需要使用。由于清理资源必须用到原管理连接的令牌，如果不先接管，项目既无法移除，旧连接也无法释放。

<Image src={imgGitlabCodeHosts} alt="集成 → 代码托管平台下的 GitLab 卡片：管理连接，以及每个 Agent 及其服务账号所属群组" width={800} />

移除连接分为两步：**断开连接**会先释放连接但保留列表行，随后删除已释放的行才会彻底移除。只要某个连接下还有正在管理的项目，系统就会阻止删除。请先按卡片提示接管或移除这些项目。

GitLab.com Free 版限制**每个顶级群组最多 100 个服务账号**，自管理 Free 或 Community Edition 实例限制**整个实例共 100 个**。只有分配了项目的 Agent 会占用配额。达到上限时，创建请求会报配额错误，已有账号不受影响。

## 监视项目 [#watch-a-project]

在 Agent 页面，进入**集成 → 添加集成 → GitLab**。

<Image src={imgGitlabAddIntegration} alt="选择了 GitLab 的添加集成对话框：选择项目、事件类型和触发条件" width={560} />

触发器依赖已有授权，不会自动新建仓库授权。目标项目必须已经是该 Agent 的工作区或已授权的其他仓库，否则添加监视项会被拒绝。

选择项目、需要监听的对象（Issue、Merge Request、Release 或任意组合），以及触发条件：

- **创建时**：当 Issue 或 Merge Request 创建时触发，以及之后在同类型讨论中被明确提及时触发。
- **任意更新**：在创建的基础上，还包括新的代码修订、标签变更和回复。
- **@ 提及**：当有人 @ 提及该 Agent 时触发。

Release 仅支持**已发布**这一种触发条件。

如果多个 Agent 同时监视同一个项目，可以在 Issue 或 Merge Request 这一行点击**添加决策**，通过[决策](/build-your-team/decisions#pick-agents-for-issues-and-pull-requests)决定由哪些 Agent 处理对应事件。

## 谁可以触发 Agent [#who-may-trigger-an-agent]

事件发生时，AgentConnect 会通过 GitLab API 实时核验内容作者在目标项目中的**当前成员身份**，不会把 Webhook 自带的标签作为鉴权依据。

只有具备目标项目 **Developer 及以上**权限的成员才能触发 Agent。如果成员状态处于待确认、已过期、权限不足、缺失或无法查询，系统会按无权限处理，不会启动 Agent。直接成员、上级群组成员以及受邀群组成员都会纳入计算，并取最高有效角色。

> 这比 GitHub 集成更严格（GitHub 允许 triage 角色）。GitLab 的 Reporter 角色没有 Merge Request 操作权限，因此门槛定在 Developer。

来自项目外部的 Merge Request 不会自动触发 Agent，当前具备 Developer 及以上权限的成员可以通过明确提及 Agent 来发起首轮任务。如果需要让 Developer 以下的用户也能触发 Agent，可以在监视项设置中将他们加入**受信任用户**。该列表的机制与 [GitHub](/connect-automate/triggers-automation/github#trusted-users) 相同，也是 Developer 以下用户触发 Agent 的唯一方式。触发权限与 Agent 后续的操作权限彼此独立：发表评论、提交评审和推送代码依然取决于你授予该 Agent 的仓库授权。

## Agent 会做什么 [#what-the-agent-does]

每个符合条件的事件都会在 Agent 所在的 Daemon 上启动一个会话，并将事件信息作为上下文传入。这些会话都会出现在[会话](/operate-govern/sessions)列表中，并附带跳回 GitLab 的链接。

- **普通回复**：由 Agent 的服务账号发送的一条普通备注。
- **评审**：先起草行内评论，再作为一次评审统一发布。**批准**会发布评审并提交绑定到当前被评审提交的批准操作。**请求修改**在 GitLab Premium 及以上版本中会阻止合并，在 Free 版本中则仅做提示、不阻止合并。AgentConnect 不会修改评审者列表。
- **运行状态**：在 Merge Request 上维护一条状态备注，随运行进度实时更新，并链接回控制台里的会话。因为 GitLab Free 不支持外部状态检查，这条备注用于展示运行状态，而不是流水线检查项。

如果想让 Agent 在某个讨论线程上重新运行，可以再次指定其服务账号为评审者、在评论中提及它，或在控制台重新运行对应会话。

Git 和 `glab` 都通过 Daemon 的[凭证代理](/operate-govern/sandboxing/credential-protection#code-host-credentials)访问 GitLab：**Agent 会话本身永远拿不到 GitLab 令牌**，且每个 Agent 只能访问自身服务账号有权访问的资源。API 读取操作照常可用，写入操作则通过 AgentConnect 提供的工具完成。

## 自管理实例 [#self-managed-instances]

上述所有功能在自管理 GitLab 实例上的使用方式完全一致。唯一需要额外完成的是每个部署只需做一次的运维配置：将部署指向你的实例、注册 OAuth 应用，并确保实例满足前提条件（GitLab 18.11+、单个 HTTPS 地址、受信任证书，以及 GitLab 可访问的回调入口）。完整步骤见 [AgentConnect OSS 上的 GitLab](/self-hosting/provider-apps#gitlab)。

不需要在各个 Daemon 上手动配置实例信息，Daemon 会自动从它所服务的 Agent 获取相关配置。
