AgentConnect 遵循一条核心架构原则：**控制平面不经过实时消息路径**。Agent 始终运行在你运维环境中的 Daemon 里，各平台的入站请求直接到达该 Daemon，或经由可选的 Relay 转发过去。

<Image src={imgHowAgentconnectWorks} alt="AgentConnect 的频道和事件到达运行在 Daemon 上的 Agent，而控制平面通过独立的控制路径进行协调" width={920} />

## 四个组成部分 [#the-four-pieces]

**Daemon** 是运行在笔记本、工作站、虚拟机或服务器上的轻量级进程，负责：

- 主动向外连接控制平面、Relay（启用时），以及 Slack Socket Mode、Telegram、Discord 和 Lark / 飞书长连接等直连通道。
- 通过 [ACP](https://agentclientprotocol.com) 启动并驱动本地已安装的 Agent Runtime（例如 Claude Code 和 Codex）。
- 在本地管理 Agent 的工作目录、Git 检出和会话记录。

**Relay** 是可选的公网入口，负责接收基于回调的 Slack 和 Lark / 飞书请求、GitHub / GitLab 与通用 Webhook、[Linear](/connect-automate/triggers-automation/linear) Agent 事件，以及 Webchat（[Playground](/build-your-team/agents/playground) 背后的浏览器通道），并将请求转发给对应的 Daemon。Relay 不会持久化消息内容。

**控制平面**负责认证、组织、权限、Agent 调度放置、集成、定时任务以及控制元数据，同时保存经过明确批准的[知识库和托管技能](/build-your-team/knowledge)，并协调所有 Daemon。

**控制台**是用于配置和观测的 Web 界面。当你查看会话记录、工具调用结果、记忆视图或工作区文件时，控制台会按需从对应的 Daemon 拉取数据，不会把正文内容写入控制平面。

## 数据存放在哪里 [#what-lives-where]

| 数据 | 存储方 |
| --- | --- |
| 实时消息和 Agent 活动 | Daemon（Relay 仅转发回调） |
| 会话记录和工具结果 | 所属 Daemon |
| 工作区和 Git 检出 | 所属 Daemon |
| Runtime 凭证 | Daemon 所在机器 |
| 机器人令牌和租户密钥 | 控制平面密钥存储 |
| 控制元数据 | 控制平面 |
| 已批准的知识库和技能 | 控制平面 |

经过授权的会话记录、工具结果、记忆和工作区读取都会按需从所属 Daemon 获取，控制平面不会持久化这些响应内容。静态密钥的加密保护取决于部署的密钥存储配置。

## 为优雅降级而设计 [#built-to-degrade-gracefully]

由于 Agent 执行和本地会话状态都由 Daemon 管理，即便控制平面短时故障，已建立的会话和本地定时任务仍可继续运行。等连接恢复后，新的任务分配、配置更新和控制台读取会自动恢复。

如果某个 Daemon 离线，它上面运行的 Agent 也会随之离线。此时控制平面仍能展示已保存的会话元数据，但在 Daemon 重新上线之前，无法拉取该 Daemon 上的会话记录和工作区内容。

## 组织与访问 [#organizations-and-access]

所有资源都归属于某个组织。组织成员身份和角色构成外层权限边界，随后 AgentConnect 再按具体资源做细粒度校验：团队可见范围控制 Agent 等资源的访问，而每个会话的元数据和会话记录则有各自独立的可见范围；Agent 之间的调用使用独立的入站和出站策略。详情见[权限概览](/operate-govern/permissions-overview)。

在启用了对应登录提供方的前提下，用户可以将[多种登录方式关联](/how-to-guides/linked-accounts)到同一个个人资料。AgentConnect Cloud 目前支持 GitHub、Google 和 Slack，自托管部署还可以额外接入 Lark 和飞书。关联后的身份会自动参与对应的会话访问权限检查。

## 托管方式 [#hosting-choices]

同一套架构同时支持自行运维完整栈的 [AgentConnect OSS](/self-hosting)，以及托管版控制台 AgentConnect Cloud。在两种方式下，Agent 和工作区都运行在 Daemon 中。本页主要介绍运行在你自有机器上的 Daemon；使用 AgentConnect Cloud 时，你也可以把 Agent 部署到[托管基础设施](/build-your-team/daemons/manage-daemons#agentconnect-cloud)上，由 AgentConnect 负责运维 Daemon 环境。

AgentConnect OSS 的认证默认关闭，开箱即用本地无认证模式。在把服务暴露到 localhost 之外前，请先配置[基于 Logto 的生产环境登录](/self-hosting/sign-in)。
