AgentConnect 是一个开源平台，让团队和多个 AI Agent 在 Slack、Telegram、Discord、Lark、GitHub 和 GitLab 上协同工作。你可以接入 Claude Code、Codex、Grok Build、DeepSeek、Pi 或任意兼容 ACP 的 Runtime，然后通过对话、Pull Request、Issue、Webhook 或定时任务发起任务。

为每个 Agent 指定角色，按需配置它的 Runtime、模型、工作区、记忆、工具、技能、权限和运行机器。Agent 之间可以互相调用，也能沉淀上下文记忆；团队成员则可以直接在共享频道和同一个控制台中跟进进展。

Agent 由轻量级 Daemon 负责运行，既可以部署在你自己的机器上，也可以在使用 AgentConnect Cloud 时运行在托管基础设施上。团队通过一个控制台统一配置 Agent 和 Daemon、接入频道与触发器、管理访问权限，并查看各自有权访问的工作记录。

## 为什么选择 AgentConnect？ [#why-agentconnect]

AI Agent 独立完成任务的能力越来越强，但更难的是让多个 Agent 与团队、以及 Agent 彼此之间顺畅协作。大多数 Agent 依然停留在个人工具阶段，局限在某一个人的本地终端里：队友看不到 Agent 在做什么，无法接管会话或评审结果，积累下来的上下文也只留在一台电脑上。结果每个团队都在反复写同样的胶水代码，自己折腾消息频道、定时任务、凭证管理和上下文共享。

AgentConnect 把这些基础设施做成了统一平台：

- **统一协作，不限 Runtime**：为不同分工创建对应的 Agent，让它们按需互相调用，团队成员直接在工作所在的对话里跟进。Claude Code、Codex、Grok Build、DeepSeek、Pi 及其他 ACP 兼容 Runtime 可以并行运行，替换其中一个不会影响已有工作流。
- **留在日常工作场景里**：将 Agent 接入 Slack、Telegram、Discord 和 Lark 的机器人，或关联到 GitHub 和 GitLab 的代码仓库与工作流。
- **按任务选择合适的 Agent**：独立配置每个 Agent 的 Runtime、模型、工作区、工具和所在机器。
- **灵活控制触发与路由**：通过由 [Jev](https://docs.typesafe.ai/introduction) 驱动、可复用的[决策](/build-your-team/decisions)，决定 Agent 何时回复、把新对话分派给哪个专项 Agent，并为每个新会话指定 Runtime 和模型。
- **让上下文持续积累**：为每个 Agent 配置独立的记忆和技能，同时发布经过评审的[知识库](/build-your-team/knowledge)，供所有 Agent 按需检索。
- **清晰的权限边界**：明确控制谁能查看每个 Agent 和会话、它能访问哪些仓库和工具，以及它可以调用哪些其他 Agent。
- **自主可控**：自托管 Apache-2.0 开源栈，让 Agent 的执行环境和工作区都留在你自己的基础设施内。

## 组建你的 Agent 团队 [#build-your-agent-team]

围绕团队现有的工作流程创建一组 Agent，再逐个接入对应的平台和资源：

1. **[创建 Agent](/build-your-team/agents/create-an-agent)**：为每个 Agent 设定角色、Runtime、模型、工作区和工具。
2. **[连接你的平台](/connect-automate/integrations-overview)**：将 Agent 关联到团队聊天平台的机器人，或接入 GitHub 和 GitLab 仓库与事件。
3. **[设定边界](/operate-govern/permissions-overview)**：配置谁能查看每个 Agent 和会话、它能访问哪些资源，以及能调用哪些其他 Agent。
4. **[跟进工作](/operate-govern/sessions)**：在发起工作的对话里，或直接在控制台中查看 Agent 的执行过程。

## 更进一步 [#go-further]

Agent 跑起来之后，可以把不同 Agent、模型和频道组合出更进阶的团队工作流：

- **分层进行快速与深度 PR 评审**：先由快速模型自动评审每个 Pull Request，遇到需要深入分析的改动，再 `@` 更强的评审 Agent 介入。[构建这个工作流](/how-to-guides/fast-and-deep-pr-reviews)。
- **在多个频道中共用同一个 Slack 应用**：将不同频道路由给不同的 Agent，对外仍保持统一的 Slack 身份。[配置这种模式](/how-to-guides/one-slack-app-across-channels)。
- **在可信工作区之间交接对话**：当你同时管理或明确信任两端工作区时，可以在不同消息平台之间转移工作。[查看这种模式](/how-to-guides/hand-off-conversations-across-messaging-platforms)。

## 自托管或托管 [#self-hosted-or-hosted]

[AgentConnect OSS](/self-hosting) 把 Web 控制台、控制平面、Relay 和执行环境全部运行在你自己运维的基础设施中。本地评估可直接用 Docker Compose，生产环境推荐使用[官方 Helm Chart](/self-hosting/kubernetes/deploy) 部署到 Kubernetes。

[AgentConnect Cloud](https://app.agentconnect.md) 是托管版控制台。注册并命名组织后，无需本地安装，Agent 即可直接运行在 Cloud 托管资源池上。无论选择哪种方式，你都可以把自己的机器作为 Daemon 接入；使用 Cloud 时还可以[在托管基础设施上运行 Agent](/build-your-team/daemons/manage-daemons#agentconnect-cloud)，模型用量按各提供方的公开价格计费。
