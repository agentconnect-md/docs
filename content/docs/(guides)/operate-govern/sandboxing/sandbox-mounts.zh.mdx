---

使用 `sandbox.mounts` 可以把参考数据、依赖缓存或工具链等宿主机目录开放给沙箱中的 Agent。工作区和 Runtime 主目录会由 Daemon 自动挂载，无需手动配置。

## 挂载选项 [#mount-options]

| 字段     | 含义                                                     |
| -------- | -------------------------------------------------------- |
| `source` | 已存在的宿主机路径（`~` 展开为 Daemon 运行用户的主目录） |
| `target` | 沙箱内的目标路径（`~` 在 microsandbox 中展开为会话主目录） |
| `mode`   | `readonly`（默认）、`writable` 或 `overlay`              |

| 模式       | 宿主机文件 | 会话内的更改             | 适用策略                          |
| ---------- | ---------- | ------------------------ | --------------------------------- |
| `readonly` | 可读       | 无法通过此挂载写入       | 两者                              |
| `writable` | 可读可写   | 与宿主机及其他会话共享   | 两者                              |
| `overlay`  | 可读       | 每个会话独立私有         | microsandbox；在 SRT 下退化为只读 |

展开 `~` 之后，`source` 和 `target` 都必须是绝对路径，且 `source` 必须在 Daemon 启动前已经存在。对于可写挂载，宿主机目录权限必须允许 Runtime 用户写入（在 `microsandbox` 中通常为 UID 10001）。

`sandbox.mounts` 会应用到 Daemon 开启的所有沙箱策略。如果某种策略无法满足某条挂载配置（例如 SRT 不支持 `source` 和 `target` 不同），该策略会被标记为不可用并报告校验错误，但 Daemon 仍可正常启动。如果你不需要该策略，可以直接关闭它（例如设置 `"srt": false`）。详见[配置 Daemon](/operate-govern/sandboxing#configure-the-daemon)。

## SRT：共享可写缓存 [#srt-share-a-writable-cache]

在 SRT 下，`source` 和 `target` 必须解析为同一路径：

```json
{
  "sandbox": {
    "mounts": [
      {
        "source": "/srv/agent-cache/pnpm",
        "target": "/srv/agent-cache/pnpm",
        "mode": "writable"
      }
    ],
    "env": {
      "PNPM_CONFIG_STORE_DIR": "/srv/agent-cache/pnpm"
    }
  }
}
```

SRT 挂载只会追加访问权限，无法用 `readonly` 规则收回工作区或其他可写挂载已经授予的写权限。

## microsandbox：映射主机目录 [#microsandbox-map-a-host-directory]

`microsandbox` 可以将宿主机目录映射到虚拟机内的不同路径：

```json
{
  "sandbox": {
    "mounts": [
      {
        "source": "/srv/reference-data",
        "target": "/reference",
        "mode": "readonly"
      }
    ]
  }
}
```

挂载不能覆盖受保护的 Runtime 路径，也不能把多个源目录映射到同一个目标路径。嵌套挂载按各自的读写模式生效。

## microsandbox：共享缓存但私有写入 [#microsandbox-share-a-cache-with-private-writes]

使用 `overlay` 可以复用宿主机上预热好的缓存，同时把每个会话的写入变更隔离开：

```json
{
  "sandbox": {
    "mounts": [
      {
        "source": "/srv/agent-cache/pnpm",
        "target": "~/.local/share/pnpm/store",
        "mode": "overlay"
      }
    ],
    "env": {
      "PNPM_CONFIG_STORE_DIR": "${HOME}/.local/share/pnpm/store"
    }
  }
}
```

宿主机目录保持只读。每个会话的新增和删除在虚拟机启停后会保留，在虚拟机重建或删除时清空；会话内新下载的依赖不会写回共享的宿主机缓存。

会话使用期间请保持宿主机缓存目录内容稳定。overlay 的源路径必须是目录，且目标路径不能与其他挂载重叠。

## 应用配置更改 [#apply-configuration-changes]

`sandbox.env` 用于为沙箱化的 Runtime 设置默认环境变量。Agent 和 Runtime 自身配置可以覆盖这些变量，但 Daemon 管控的 `HOME`、XDG 和安全相关变量除外。变量值按字面量传递（上面示例中的 `${HOME}` 是由 `pnpm` 自行展开的）。

修改 `config.json` 后请重启 Daemon。仅改动环境变量时，会在 Runtime 重启后生效；如果改动了挂载、虚拟机资源、凭证布局或镜像内容，受影响的虚拟机会在刷新或下次使用时重建。宿主机挂载的文件会保留，虚拟机本地文件、Docker 数据和 overlay 写入会被重置。

如果正在从旧版配置迁移：

- 将 `security.sandboxReadRoots` 改为 `readonly` 挂载，将 `security.sandboxWriteRoots` 改为 `writable` 挂载（使用 SRT 时保持 `source` 和 `target` 一致）。
- 将每条挂载中旧的 `readOnly` 字段替换为 `mode`。
- 迁移完成后删除所有旧字段。只要残留任意旧字段，Daemon 就会拒绝启动。
