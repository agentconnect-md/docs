Two console pages help you track model spend and see where it came from.

**Analytics** charts metered tokens and cost. It's always available, including on self-hosted deployments with no billing service, where it reports usage metered by your own daemons. **Billing** tracks your prepaid credit balance and transaction ledger, and appears only on deployments running a billing service.

The two pages don't measure the exact same spend. Analytics reports all metered usage, including agents on daemons you connect yourself. Those agents use the provider credentials on your machines, so their traffic is counted in Analytics but never billed by AgentConnect. Only metered Cloud usage deducts from your credit balance. See [Cloud pricing](/build-your-team/daemons/manage-daemons#pricing) for rates and what happens when credits run out.

## Billing

### Balance

The balance card shows the remaining credit balance for Cloud work alongside your organization's status:

- **Serving**: Cloud placements are taking model traffic normally.
- **Suspended**: Your balance reached zero and Cloud placements stopped taking new model traffic. Adding credits resumes them.
- **Unconfirmed**: A recent change to the organization's access hasn't been confirmed upstream yet, so AgentConnect doesn't assume either state. This isn't a payment issue and resolves on its own.

### Add credits

Owners see **Add credits**, which opens a Stripe checkout page for the amount you enter. Every member can view the balance and ledger, while only Owners can top it up. Completed purchases include a **Receipt** link on their ledger row once the receipt is ready, which can take a moment after payment finishes.

Leaving the Stripe page without paying charges nothing. A payment that's still settling shows as pending rather than failed. It resolves automatically and shows its own banner separate from the balance status above.

### Activity

The Activity chart groups ledger entries over the last **24h**, **7d**, **30d**, or **90d** in your local time zone, and toggles between **Usage** and **Top-ups**. Use it to see when spend happened; use Analytics to see what drove it.

### Transactions

The Transactions table lists ledger entries newest first, filtered by **Usage** or **Top-ups**, and loads more rows as you page through it. Credit rows include a type (**Credit purchase**, **Adjustment**, **Promotional credit**, or **Refund**), and adjustments may include a note from whoever recorded them.

Usage rows list the agents behind the charge as chips showing each one's share. Agent names follow your access to each Agent, matching the Agents page. Owners see every current organization Agent; other members see only Agents allowed by [Team visibility](/operate-govern/permissions-overview/team-visibility). Hidden or deleted Agents roll up into a single unnamed entry with no agent count, shown separately from the `+N` overflow for named chips. Session audiences don't change this billing attribution.

## Analytics

**Analytics** charts tokens and cost over the last **24 hours**, **7 days**, **30 days**, or **90 days**, grouped **By agent**, **By runtime**, or **By model**. On narrow screens, the 90-day range isn't offered. Click a series in the legend to hide it, and click it again to bring it back.

On deployments running a daemon pool, a **source** filter lets you pick which ingress metered the session:

- **All**: All metered usage, billed or not.
- **Cloud**: Sessions metered by the managed pool. These deduct from your credit balance.
- **Cluster**: The same filter on a self-hosted deployment, covering sessions metered by your own daemon pool using your deployment's model access. Counted here with no AgentConnect balance.
- **Daemons**: Sessions metered by daemons you connect yourself. Counted here and never billed.

The source is recorded when each session runs, so moving an agent between a daemon and the pool changes where its *future* usage lands without rewriting history.

## Who sees what

| Capability | Owner | Other members |
| --- | --- | --- |
| Read the balance, Activity, and Transactions | ✅ | ✅ |
| Read organization-wide Analytics totals and source totals | ✅ | ✅ |
| See Analytics agent/model breakdowns and spend over time | Complete organization usage | Only usage from Agents and Sessions they can access |
| See an agent named on a billing usage row | All current organization Agents | Only Agents they can see |
| Add credits | ✅ | ❌ |

Owners see complete Analytics attribution, including spend from restricted Agents, another member's Private sessions, and provider-restricted sessions. These aggregates don't include session IDs, titles, transcripts, or tool details. Reading an individual session still requires access through its [session audience](/operate-govern/permissions-overview/session-visibility).

For Collaborators and Viewers, Analytics attribution requires access to both the Agent and the Session. Unattributed spend stays in the organization total and appears as **Restricted usage**. Attributed agent rows plus that rollup equal the total. Their spend chart plots only attributed usage, so it may add up to less than the organization total. Source totals stay organization-wide for every role.

For example, an Agent with $4 of shared-session spend and $7 from another member's Private session contributes $11 to the organization total. An Owner sees all $11 attributed to that Agent. A Collaborator who can access the Agent and only the shared session sees $4 attributed to the Agent and $7 as unattributed usage.
