**会话**记录了 Agent 在 Slack 线程、GitHub 事件、Linear 委派、Webhook、定时任务以及 Playground（控制台中显示为“试用”）中的每一次运行。你在列表中看到的是各条[会话可见范围](/operate-govern/permissions-overview/session-visibility)允许访问的记录。Agent 的团队可见范围单独控制对该 Agent 的访问，不会隐藏你有权查看的会话。

<Image src={imgSessionDetail} alt="一条会话记录，其中 Agent 的计划、文件编辑和工具输出已展开" width={900} />

## 查找会话 [#find-a-session]

在会话列表中，可以按 Agent 或来源筛选记录，也可以从定时运行直接追溯到对应的定时任务。如果你有权查看某条会话，但无权访问所属 Agent，列表中仍会显示该 Agent 的名称作为筛选标签（不可点击跳转）。当多个 Agent 参与同一个受支持的对话时，列表会把它们的会话合并为一行展示。

<Image src={imgSessionsList} alt="会话列表，可按 Agent、集成、频道或触发器筛选" width={900} />

## 查看一次运行 [#review-a-run]

每条会话都会记录来源、Agent、参与者、Daemon、Runtime 和模型，以及耗时、Token 用量、费用（如有）和工具调用记录。当来源平台提供链接时，会话页会直接给出原始对话的跳转入口。

会话会保存当时的执行配置快照：即使你之后修改了该 Agent 的配置，页头显示的依然是这次运行*实际使用*的配置。

### 会话记录 [#the-transcript]

会话记录将消息、推理过程、计划、工具调用和文件修改分块展示。工具调用会附带可用的输入和输出，文件修改会附带 diff，方便排查 Agent 是如何得出结果的。

## 当运行请求权限时 [#when-a-run-asks-for-permission]

根据 Agent 的权限模式，Runtime 可能会在轮次中途停下来，在执行操作前请求确认。此时轮次会等待审批，你可以在三个地方处理：

- **在控制台中**：任何有权限编辑该 Agent 的人都可以审批，包括不在指定成员列表里的组织所有者。你可以从 Agent 页面操作，或者在会话可见范围允许时直接从会话页面操作。通知铃铛会新增一条未读的**需要审批**提醒并指向等待中的会话，审批完成后自动标记为已解决。在 Playground 或 [Agent 对话 API](/connect-automate/agent-chat-api) 对话中，除非 Agent 设为**和 agent 对话**，对话所有者也可以直接在输入框上方的待审批请求中处理。
- **在 Slack 或 Teams 私信中**：如果对话里没有发出审批卡片，或者对话里只允许编辑者审批但发起人不是编辑者，Agent 会把同一张卡片私信发给一位有审批权限且已[关联 Slack 或 Microsoft 账号](/how-to-guides/linked-accounts)的成员。私信里附带会话链接，在 Slack 上还会附上触发该次工作的原始消息链接。在私信中审批与在控制台中操作效果完全一致，控制台会记录最终审批人。
- **在对话中**：当 Agent 的[**聊天中可以做什么**](/build-your-team/agents/configure-an-agent#what-people-can-do-in-chat)允许批准工具调用时（默认开启），Slack、Telegram、Discord、Lark / 飞书、Google Chat 和 Microsoft Teams 会直接把审批卡片发到当前工作位置（对话线程、Telegram 话题或回复链）。卡片提供 Runtime 自身的选项，在 Runtime 支持时也包括“始终允许”该工具。如果 Slack 开启了**遵循 Slack 访问权限**，或 Teams 开启了**要求 Microsoft Teams 访问权限**，则只有 Agent 的编辑者可以操作；未启用权限同步时，对话中的任何成员都可以审批。无权操作的人点击按钮时，只有本人会看到拒绝提示，其他人看到的卡片状态不变。

无论从哪个入口提交，以最先到达的审批结果为准，卡片随即更新为最终审批人及所选结果。

如果权限级别设为**和 agent 对话**，或者对话设为**关闭**或**按决策**，对话中不会发出审批卡片，而是发出一条简短提示，说明当前有待 Agent 编辑者处理的审批。在支持审批卡片的平台上，审批完成后这条提示会更新为最终结果。QQ 不支持审批卡片，因此 QQ 对话始终只发提示，需要在控制台中审批。与其他组织共享的对话也不会发卡片，审批会通过私信发给你所在组织的成员。[Linear](/connect-automate/triggers-automation/linear) 会话则会在 Issue 的活动动态中发布同样的提示，并附上控制台链接。

发送 Slack 和 Teams 私信审批时，AgentConnect 只选一位接收人。系统会优先检查 Agent 的 Slack 工作区，再检查 Teams 组织，并在每个平台按以下顺序依次筛选候选人：

1. 发送触发该轮次消息的人。
2. 会话所有者。
3. 对于可见范围为指定成员的 Agent，按保存顺序排列的指定成员。
4. Agent 的创建者。

候选人必须同时满足：当前属于该组织、有权限编辑该 Agent，并且在该工作区关联了 Slack 身份（或为 Teams 关联了 Microsoft 账号）。所有者即使不在指定成员列表里也符合资格，但仅凭所有者身份不会自动进入候选列表，只有按上述顺序选中时才会收到私信。

当接收人点击审批按钮时，AgentConnect 会重新校验编辑权限和关联账号。如果找不到符合条件的接收人，审批仍可在控制台中处理，对话中也会保留等待提示。

## 当多个 Agent 共享一个对话时 [#when-several-agents-share-a-conversation]

每个 Agent 依然在各自的会话中运行，使用各自的配置和权限。在多 Agent 参与的 Playground 或受支持的 IM 对话（Slack、Telegram、Discord、Lark、飞书）中，控制台会将这些参与者的会话整合为一个对话视图，按 Agent 标注各自的活动并汇总当前用量。

这种整合只是展示视图，不会改变权限边界。你只能看到各条会话可见范围允许的内容，包括所属 Agent 页面对你隐藏但会话本身可读的记录。关于多 Agent 协作方式，见[多 Agent 工作模式](/build-your-team/agents/multi-agent-work-modes)。

## 会话记录存放在哪里 [#where-transcripts-live]

控制平面只保存会话元数据，例如标题、状态、时间戳和 Token 总量。具体的对话消息和工具输出内容保留在运行该会话的 Daemon 本机上。

有权限的成员打开会话记录时，控制台会按需从所属 Daemon 拉取内容展示，不会把正文持久化到控制平面。当 Daemon 离线时，会话元数据依然可见，但详细记录要等 Daemon 重新上线后才能加载。

## 保留与清理 [#retention-and-cleanup]

每台 Daemon 默认将已完成会话的内容保留 **7 天**。添加或编辑 Daemon 时，可以通过**过期会话**选择预设周期、输入自定义天数或设为永久保留。

超过保留期后，Daemon 会清理该会话的记录、工具详情以及为它创建的 Git 工作树。控制平面中仍保留会话元数据，因此该会话还会出现在列表里，并注明内容已按保留策略清理。

正在进行的会话不会被清理。如果会话工作树中还有未提交的改动，或存在尚未推送到远程的提交，AgentConnect 也会保留该工作树。

## 会话可见范围 [#session-audience]

对于直接管理的会话，当匹配到的所有者有权修改可见性时，页头会显示**所有人 / 私密**切换项。对于绑定外部平台的会话，在组织于**设置 → 会话访问权限**中开启对应选项后，可改为遵循 **Slack 成员**、**飞书 / Lark 成员**或 **GitHub 成员**。将会话设为私密会立即隐藏会话记录，并可能影响后续的记忆捕获；收紧权限前请先查看[会话可见范围](/operate-govern/permissions-overview/session-visibility)。

## 跨平台交接保持独立 [#cross-platform-handoffs-stay-separate]

对话分组不会合并不同平台或不同线程。跨平台交接会在源平台保留原有会话，并在目标平台新建一条关联会话。回复只会留在各自所在的平台上，除非 Agent 明确把结果回传给源平台。

可以参考[在受信任的工作区之间交接对话](/how-to-guides/hand-off-conversations-across-messaging-platforms)，里面包含从 Slack 到 Discord 的完整示例和可复用的 Agent 指令。

## Agent 之间的交接 [#agent-to-agent-handoffs]

委派给其他 Agent 的任务会在关联的子会话中运行，并继承父会话的可见范围。只要你有权查看父会话，即使无法打开目标 Agent，也可以查看这个子会话。目标 Agent 的名称仅作为不可点击的上下文展示，不会附带任何 Agent 配置或工作区访问权限。

## 实时会话 [#live-sessions]

进行中的会话会实时更新。对于你有权继续的会话，会话页面下方会提供输入框：

- **Playground 和 webchat**：照常直接在浏览器中继续对话。
- **聊天平台**（Slack 线程、Telegram 或 Discord 聊天、Lark / 飞书对话）：你在控制台发送的消息会先同步到原始对话线程中，让原频道里的人看到是什么改变了 Agent 的上下文，随后 Agent 按该会话原有的输出模式回复。
- **GitHub、GitLab、Webhook 或定时任务事件**：仅在控制台中继续，不会向 Pull Request、Issue 或原始事件来源回发任何内容。

继续会话属于写操作，因此查看者无法操作，私密会话也仅限所有者本人继续。此外，继续会话还需符合会话可见范围，且所属 Agent 对你可见、对应 Daemon 在线。只要缺少其中任意一项条件，页面就会说明具体原因，而不会显示输入框。
