组织可以让成员通过自己的身份提供方登录。整个配置分为三步，你可以在任意一步停下来：

| 步骤 | 带来的变化 |
| --- | --- |
| [验证域名](#verify-a-domain) | 证明组织拥有该邮箱域名，此时不影响现有登录方式。 |
| [启用连接](#activate) | 已验证域名下的邮箱只能通过你的身份提供方登录。 |
| [强制](#enforce-single-sign-on) | 所有成员（包括所有者）必须通过 SSO 会话才能访问组织。 |

是否自动接纳成员在[新成员](#new-members)中单独设置，无论是否配置了 SSO 连接都可以使用。

所有者可以在**设置 → 单点登录**中完成全部配置。在配置好域名或连接后，其他成员也能看到该标签页，但无法修改。

<Image src={imgSsoSettingsTab} alt="单点登录标签页：一个已验证的域名和一条已强制的连接" width={640} />

## 验证域名 [#verify-a-domain]

1. 在**域名**区域选择**添加域名**，输入域名（例如 `acme.example`）。
2. 在你的 DNS 服务商处，按页面显示添加对应的 TXT 记录：

   | 类型 | 名称 | 值 |
   | --- | --- | --- |
   | TXT | `_agentconnect-challenge.acme.example` | `agentconnect-verification=…` |

3. 点击**验证**，该行状态会从**待验证**变为**已验证**。

<Image src={imgSsoDomainPending} alt="待验证的域名，以及需要创建的 TXT 记录" width={640} />

刚添加完记录就提示**未找到记录**，通常是因为 DNS 尚未生效，稍等片刻再点**验证**即可。待验证的域名如果在七天内未完成验证会被清除，之后可以重新添加。

- 每个域名只能归属一个组织。如果其他组织先完成了验证，该行会显示**已被其他组织验证**。
- 域名采用精确匹配。如果成员使用 `eu.acme.example` 邮箱，需要将其单独添加为一个域名。
- 每个组织最多可以添加 20 个域名。
- 请长期保留这条 TXT 记录。AgentConnect 每天会重新检查一次，如果记录丢失，域名会被标为 **DNS 记录缺失**，在恢复之前无法启用连接。

## 配置连接 [#set-up-the-connection]

域名验证通过后，**连接**区域会出现**配置连接**按钮。选择你的身份提供方使用的协议。保存前，对话框就会展示需要登记到身份提供方的参数，你可以先去身份提供方创建应用，再把生成的凭据填回来。

**OIDC**

| 字段 | 填写内容 |
| --- | --- |
| **Issuer** | 身份提供方的 issuer URL |
| **Client ID**、**Client secret** | 身份提供方为该应用签发的凭据 |
| **Scopes** | 默认为 `openid email profile`，仅在身份提供方需要额外 scope 才返回邮箱时补充 |
| **回调 URL** | 复制后在身份提供方登记为重定向 URI |

<Image src={imgSsoConnectionOidc} alt="OIDC 的连接对话框，其中的回调 URL 需要登记到身份提供方" width={480} />

**SAML**

| 字段 | 填写内容 |
| --- | --- |
| **元数据** | 身份提供方的元数据 URL，或元数据 XML |
| **邮箱属性** | 存放邮箱地址的属性名（默认为 `email`） |
| **姓名属性** | 存放显示名称的属性名（默认为 `name`） |
| **ACS URL**、**Entity ID** | 复制后登记到身份提供方 |

连接创建后协议无法直接更改。如需切换协议，请先删除连接再重新配置，届时会生成新的登记参数。

连接仅对已验证域名下的邮箱生效。如果身份提供方未返回邮箱，或返回了其他域名下的邮箱，登录会被拒绝。AgentConnect 会直接采信身份提供方返回的邮箱，请确保所接入的身份提供方不允许用户自行修改邮箱。

## 测试登录 [#test-the-sign-in]

新建的连接初始状态为**未测试**。点击**测试登录**，通过身份提供方完成一次登录后会跳转到结果页：

- **登录测试通过**：显示身份提供方返回的邮箱地址。点击**返回设置**，连接状态变为**已测试**。
- **登录测试未通过**：说明失败原因。如果身份提供方未返回本组织域名下的邮箱，页面会列出**身份提供方发送的属性**（仅显示属性名），并标出包含**本组织域名的邮箱**的属性。将其设为**邮箱属性**（OIDC 则调整邮箱 claim），然后重新测试。

开始测试前请注意两点：

- 测试开始后的十分钟内，你域名下的邮箱只能通过这条连接登录，效果与连接已启用相同。
- 如果身份提供方返回了其他人的邮箱，你会被登录到对方账号，之后需要重新切回自己的账号。

日后修改连接设置会使状态重置为**未测试**，需要重新测试通过。

## 启用 [#activate]

当至少有一个已验证域名且连接已通过测试时，可以点击**启用**。启用后：

- 已验证域名下的邮箱只能通过 SSO 登录，其他登录方式会被拒绝，对应域名行会显示**只能通过 SSO 登录**。
- 此前已用这类邮箱注册过账号的成员会保留原账号。首次通过 SSO 登录时会自动进入同一个账号，成员关系和个人设置不变。
- 之后新增并验证的域名，在弹窗确认后也会立即纳入 SSO 登录范围。

启用连接只改变登录方式，不会自动添加或移除组织成员。

## 成员如何登录 [#how-members-sign-in]

成员在登录页选择**使用 SSO 继续**，输入**工作邮箱**，页面会自动跳转到你的身份提供方。SSO 登录页有独立地址（控制台的 `/login/sso`），习惯使用 SSO 的成员可以直接收藏该链接，跳过首屏登录页。

<Image src={imgSignInSso} alt="带有“使用 SSO 继续”和“上次使用”标签的登录页" width={640} />

<Image src={imgSignInSsoPage} alt="要求填写工作邮箱的 SSO 页" width={640} />

登录页会用**上次使用**标记浏览器最近一次使用的登录方式，SSO 页也会自动填入上次输入的邮箱。如果输入的邮箱所属域名没有启用 SSO 连接，页面会提示**这个邮箱没有设置单点登录。**

## 新成员 [#new-members]

验证至少一个域名后，**设置 → 成员**页面会出现**新成员**设置：

| 选项 | 谁会加入 |
| --- | --- |
| **仅邀请**（默认） | 仅限所有者手动添加的人，或通过邀请链接加入的人 |
| **域内自动加入** | 除上述人员外，使用已验证域名邮箱登录的任何人都会自动加入 |

<Image src={imgSsoNewMembers} alt="新成员设为域内自动加入" width={640} />

通过域名自动加入的成员会成为**协作者**，且该规则仅对每人触发一次：

- 如果所有者事后移除了该成员，对方下次登录时不会再被自动加回，需要重新邀请。
- 已经是组织成员的用户保留原有角色。
- 开启该选项时已经处于登录状态的用户，会在下次重新登录时加入组织。

这项设置不依赖 SSO 连接。只要组织有已验证域名，该域名下的用户通过任意方式登录都会自动加入。移除最后一个已验证域名后，设置会自动恢复为**仅邀请**。

域名匹配依据的是用户 AgentConnect 账号上的邮箱。如果有人已经离职，但仍能通过其他方式登录该账号，系统依然会将其视为该域名下的用户。请及时在**成员**列表中移除离职人员；如果希望完全由身份提供方把控访问权限，请[强制使用单点登录](#enforce-single-sign-on)。

## 强制使用单点登录 [#enforce-single-sign-on]

启用连接可以限制域内邮箱的登录方式，但同一个账号可能绑定了多种登录方式。强制 SSO 可以堵上这个缺口：所有成员（包括所有者）必须使用通过该 SSO 连接登录的浏览器会话，才能进入组织。

在**已启用**的连接上可以看到**强制**按钮。执行强制操作需要满足三个条件：你是组织所有者、你的邮箱位于已验证域名下、当前浏览器会话是通过 SSO 登录的。如果当前不是 SSO 会话，弹窗会提供**使用 SSO 登录**按钮，登录完成后会自动返回。

连接处于**已强制**状态时：

- 通过其他方式登录的成员，在组织页面会看到**_Acme_ 需要通过单点登录进入**的提示和**使用 SSO 登录**按钮。他们对其他组织的访问不受影响。
- 邮箱不在已验证域名下的成员无法通过 SSO 登录，从而失去访问权限。如果需要外包人员继续访问，请在身份提供方中为他们分配本组织域名下的邮箱，或不要开启强制。
- 为该组织创建个人 API 密钥或批准 OAuth 授权，同样需要 SSO 会话。此前已签发的 API 密钥、OAuth 令牌和服务账号仍会继续生效，成员离职时请手动撤销其持有的凭证。

<Image src={imgSsoRequired} alt="没有 SSO 会话的成员看到的页面：组织需要通过单点登录进入" width={560} />

点击**停止强制**后，成员可以重新通过任意已登录会话访问组织，同时 SSO 连接保持启用。编辑连接设置或停用连接也会自动关闭强制，需要所有者再次手动开启。

如果强制期间身份提供方发生故障导致所有所有者都无法登录，部署管理员可以代为关闭强制。

## 修改或移除 [#change-or-remove]

| 操作 | 结果 |
| --- | --- |
| **编辑** | 新设置立即生效。连接保持启用，状态重置为**未测试**（需重新测试通过），并自动关闭强制。对于 OIDC，除非点击**替换**或修改了 issuer，否则已保存的 client secret 会保留。 |
| **停用** | 已验证域名下的邮箱恢复为允许任意方式登录。此前已通过该连接登录的用户仍可继续使用。 |
| **删除连接**（位于**编辑**中） | 删除连接及其建立的 SSO 登录方式。用户账号本身保留，用户可改用其他方式登录。 |
| **移除域名** | 待验证的域名随时可以移除；已验证的域名只有在组织没有 SSO 连接时才能移除。 |

如果连接显示为**需要重新配置**，说明其在登录服务侧的配置已丢失。请选择**重新配置**并重新填写；需要登记到身份提供方的参数可能已经变化。

## 在个人资料里 [#on-your-profile]

**个人资料 → 登录方式**会将组织 SSO 连接为你建立的身份显示为 **SSO**，并附带对应邮箱。该项无法在个人资料中手动解绑，只有当组织删除连接时才会自动移除。其他登录方式见[关联账号](/how-to-guides/linked-accounts)。

## 自托管 [#self-hosting]

以上流程适用于运维方允许各组织自行配置 SSO 的部署。如果是单一公司内部使用的自托管部署，更常见的做法是由运维方为整个部署配置一条全局连接器，并配套独立的**新成员**设置。两种模式在[登录](/self-hosting/sign-in#single-sign-on)中均有说明。
