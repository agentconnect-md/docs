组织可以让自己的人通过组织的身份提供方登录。下面三件事层层递进，做到哪一步都可以停下：

| 步骤 | 带来的变化 |
| --- | --- |
| [验证域名](#verify-a-domain) | 证明组织控制着某个邮箱域名。其他都不变。 |
| [启用连接](#activate) | 已验证域名下的邮箱只能通过你的身份提供方登录。 |
| [强制](#enforce-single-sign-on) | 所有成员（包括所有者）只有在 SSO 会话里才能进入组织。 |

谁能成为成员是另一个独立的选择，见[新成员](#new-members)，有没有连接都可以用。

这些都由所有者在**设置 → 单点登录**里配置。其他成员在有域名或连接可看之后能看到这个标签页，但不能修改。

## 验证域名 [#verify-a-domain]

1. 在**域名**里选择**添加域名**，输入域名，例如 `acme.example`。
2. 到你的 DNS 服务商那里，按这一行显示的内容创建 TXT 记录：

   | 类型 | 名称 | 值 |
   | --- | --- | --- |
   | TXT | `_agentconnect-challenge.acme.example` | `agentconnect-verification=…` |

3. 选择**验证**。这一行从**待验证**变为**已验证**。

刚建好记录就看到**未找到记录**，通常是 DNS 还没生效，等一会儿再选**验证**。待验证的域名七天内没有通过验证会被清掉，之后可以重新添加。

- 一个域名只属于一个组织。如果别的组织先验证了它，你这一行会显示**已被其他组织验证**。
- 域名是精确匹配的。如果有人用 `eu.acme.example` 下的邮箱，要把它单独添加为一个域名。
- 一个组织最多可以有 20 个域名。
- TXT 记录要一直保留。AgentConnect 每天会重新查询一次，记录不在时这一行会标为 **DNS 记录缺失**，在它恢复之前无法启用连接。

## 配置连接 [#set-up-the-connection]

有了已验证的域名之后，**连接**里会出现**配置连接**。选择你的身份提供方使用的协议。对话框在你保存之前就会显示需要登记到身份提供方的值，所以可以先去那边创建应用，再带着它签发的信息回来填写。

**OIDC**

| 字段 | 填写 |
| --- | --- |
| **Issuer** | 身份提供方的 issuer URL |
| **Client ID**、**Client secret** | 身份提供方为这个应用签发的凭据 |
| **Scopes** | 默认 `openid email profile`，除非身份提供方需要更多 scope 才返回邮箱 |
| **回调 URL** | 供你复制：在身份提供方那里登记为重定向 URI |

**SAML**

| 字段 | 填写 |
| --- | --- |
| **元数据** | 身份提供方的元数据 URL，或元数据 XML |
| **邮箱属性** | 携带邮箱的属性，默认是 `email` |
| **姓名属性** | 携带显示名称的属性，默认是 `name` |
| **ACS URL**、**Entity ID** | 供你复制：登记到身份提供方 |

连接建好之后协议就固定了。要换协议，先删除连接再重新配置，届时要登记的值也会是新的。

一条连接只对你已验证域名下的邮箱有效。没有返回邮箱、或返回了其他域名邮箱的登录会被拒绝。AgentConnect 直接采用身份提供方返回的邮箱，所以请使用不允许用户自行填写邮箱的身份提供方。

## 测试登录 [#test-the-sign-in]

新建的连接显示为**未测试**。选择**测试登录**：你会通过身份提供方登录一次，然后落在结果页上。

- **登录测试通过**会显示返回的邮箱。选择**返回设置**，连接此时显示为**已测试**。
- **登录测试未通过**会说明缺了什么。如果身份提供方没有返回你域名下的邮箱，页面会列出**身份提供方发送的属性**（只列名称），并标出其中带有**本组织域名的邮箱**的那些。把其中一个设为**邮箱属性**（OIDC 则调整邮箱 claim），然后重新测试。

开始测试前要知道两点：

- 测试开始后的十分钟内，你域名下的邮箱只能通过这条连接登录，和连接启用之后一样。
- 如果身份提供方返回的是别人的邮箱，你会登录到那个账号，之后需要重新登录回自己的账号。

之后修改连接的设置，会让它回到**未测试**，直到再次测试通过。

## 启用 [#activate]

域名已验证、连接已测试之后，可以选择**启用**。从这一刻起：

- 已验证域名下的邮箱只能通过 SSO 登录，其他登录方式对它们会被拒绝；每一行域名会显示**只能通过 SSO 登录**；
- 已经用这类邮箱注册过账号的人保留原账号：他们第一次通过 SSO 登录时会进入同一个账号，成员关系和设置都不变；
- 之后再验证的域名，在确认后一经验证就纳入其中。

启用改变的是这些邮箱的登录方式，不会增加或移除任何成员。

## 成员如何登录 [#how-members-sign-in]

成员在登录页选择**使用 SSO 继续**，输入**工作邮箱**，然后被带到你的身份提供方。SSO 页有自己的地址，即控制台上的 `/login/sso`，一直这样登录的人可以把它收藏起来，跳过登录页。

登录页会给这个浏览器上次用过的方式标上**上次使用**，SSO 页也会填好上次用过的邮箱。如果邮箱的域名没有连接，会提示**这个邮箱没有设置单点登录。**

## 新成员 [#new-members]

有了已验证的域名之后，**设置 → 成员**里会出现**新成员**：

| 选项 | 谁会加入 |
| --- | --- |
| **仅邀请**（默认） | 只有所有者添加的人，或打开邀请链接的人 |
| **域内自动加入** | 另外，用已验证域名下的邮箱登录的任何人 |

通过域名加入的人会成为**协作者**，且只加入一次：

- 之后被所有者移除的人，下次登录不会再被加回来；要让他们回来，请重新邀请；
- 已经是成员的人保留原有角色；
- 你做出选择时已经登录的人，会在下次登录时加入。

这个选择不需要连接。只要有已验证的域名，这个域名下的人用任何方式登录都会加入。移除最后一个已验证域名会让组织回到**仅邀请**。

这里看的是对方 AgentConnect 账号上的邮箱。已经离开公司、但还能用其他方式登录这个账号的人，仍然算在你的域名下。请在**成员**里移除他们；如果希望由身份提供方来决定谁能进入，请[强制使用单点登录](#enforce-single-sign-on)。

## 强制使用单点登录 [#enforce-single-sign-on]

启用的连接限制了域名下的邮箱怎么登录，但一个账号可以有多种登录方式。强制补上了这个缺口：所有成员（包括所有者）只有在通过这条连接登录的浏览器会话里才能进入组织。

**强制**出现在**已启用**的连接上。你必须是所有者、自己的邮箱在已验证域名下、并且当前会话是通过 SSO 登录的，才能强制。如果当前会话不是，对话框会提供**使用 SSO 登录**，登录后回到原处。

连接显示为**已强制**期间：

- 用其他方式登录的成员，在原本显示组织的地方会看到**_Acme_ 需要通过单点登录进入**和**使用 SSO 登录**。他们的其他组织不受影响。
- 邮箱不在已验证域名下的成员无法通过 SSO 登录，会失去访问权限。请在身份提供方那里给外包人员分配你域名下的邮箱，或者不要强制。
- 为这个组织创建个人 API 密钥或批准 OAuth 授权，同样需要 SSO 会话。之前签发的密钥、OAuth 令牌和服务账号照常可用，所以有人离开时要撤销他持有的那些。

**停止强制**之后，成员可以用任何方式登录后进入组织，连接仍保持启用。修改连接设置或停用连接也会结束强制，只有所有者再次强制才会恢复。

如果在强制期间身份提供方出了故障，没有任何所有者能登录，部署管理员可以关闭强制。

## 修改或移除 [#change-or-remove]

| 操作 | 结果 |
| --- | --- |
| **编辑** | 新设置立即生效。连接保持启用，在再次测试通过前显示为**未测试**，并且不再强制。对 OIDC，除非你选择**替换**或修改了 issuer，已保存的 client secret 会保留。 |
| **停用** | 你域名下的邮箱可以重新用任何方式登录。通过这条连接登录过的人仍然可以继续用它。 |
| **删除连接**（在**编辑**里） | 连接以及它建立的 SSO 登录方式都会被删除。账号保留，需改用其他方式登录。 |
| **移除域名** | 待验证的域名随时可以移除；已验证的域名只有在组织没有连接时才能移除。 |

显示为**需要重新配置**的连接，是它在登录服务那边的设置丢失了。选择**重新配置**并重新填写；需要登记的值可能已经变了。

## 在个人资料里 [#on-your-profile]

**个人资料 → 登录方式**会把组织的连接给你建立的身份列为 **SSO**，并显示对应的邮箱。它不能在那里解除关联；组织删除连接后它会消失。其他登录方式见[关联账号](/how-to-guides/linked-accounts)。

## 自托管 [#self-hosting]

以上内容适用于运维方允许各组织自行配置 SSO 的部署。属于单个公司的部署，更常见的做法是由运维方为整个部署配置一条连接，并带有它自己的**新成员**选项。两种方式都在[登录](/self-hosting/sign-in#single-sign-on)里说明。
