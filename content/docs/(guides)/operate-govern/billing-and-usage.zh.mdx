有两个控制台页面用来回答“这花了多少钱，是谁花的”。

**分析**以图表展示计量的 Token 和成本，并且始终可用——包括在没有账单服务的自托管部署上，此时它报告的是你自己的 Daemon 所计量的数据。**账单**保存预付额度余额及其背后的账目，只出现在运行了账单服务的部署上。

两者覆盖的并不是同一笔钱。分析会报告所有被计量的用量，而运行在你自行连接的 Daemon 上的 Agent 使用的是那些机器上配置的提供方凭证——这些流量会被计入，但永远不会被计费。只有被计量的云端工作才会扣减余额。有关费率以及额度用尽后会发生什么，请参阅[云端定价](/build-your-team/daemons/manage-daemons#pricing)。

## 账单 [#billing]

### 余额 [#balance]

余额卡片显示的就是云端工作所扣减的数字，旁边是组织的状态：

- **服务中**——各云端放置正在正常接收模型流量。
- **已暂停**——余额已用尽，云端放置已停止接收新的模型流量。充值后会恢复。
- **待确认**——组织访问权限的一项变更尚未在上游得到确认，因此 AgentConnect 不作任何一方的断言。这不是付款状态，它会自行解决。

### 充值 [#add-credits]

所有者会看到**充值**，它会按输入的金额打开一个 Stripe 结账页面。每位成员都可以查看余额和账目；只有所有者可以充值。购买完成后，其账目行会在收据可用时提供一个**收据**链接，这可能比付款本身完成稍晚片刻。

如果你未付款就离开了 Stripe 页面，不会产生任何扣费。仍在结算中的付款会显示为待处理而不是失败——它会自行完成，并有自己的横幅提示，与上面的余额状态分开。

### 活动 [#activity]

活动图表按你自己的时区，把最近 **24h**、**7d**、**30d** 或 **90d** 的账目分时段汇总，并可在**用量**和**充值**之间切换。用它来查看支出发生的时间，而不是支出的用途；后者由分析页面回答。

### 交易记录 [#transactions]

交易记录表按最新在前的顺序列出账目，可筛选为**用量**或**充值**，并在你翻页时继续加载更多。额度行带有类型——**购买额度**、**调整**、**促销额度**或**退款**——调整项可能附带记录者留下的备注。

用量行会列出花费这笔钱的 Agent，以标签的形式显示并注明各自的份额。名称的显示遵循你对 Agent 本身的访问权限，与 Agents 页面一致。所有者可以看到组织当前的每一个 Agent；其他成员只能看到[团队可见范围](/operate-govern/permissions-overview/team-visibility)允许的 Agent。隐藏或已删除的 Agent 会折叠为一个未命名的汇总项，不显示 Agent 数量，并与命名标签的 `+N` 溢出项分开显示。会话可见对象不会改变这种账单归属。

## 分析 [#analytics]

**分析**以图表展示最近 **24 小时**、**7 天**、**30 天**或 **90 天**的 Token 和成本，可**按 Agent**、**按 Runtime** 或**按模型**分组。在窄屏幕上不提供 90 天范围。在图例中选中某个数据系列会将其隐藏，再次选中则恢复显示，因此你可以把干扰性的数据系列从图中去掉。

在运行了 Daemon 池的部署上，**来源**筛选器可以选择由哪个入口计量了会话：

- **全部**——所有用量，不论是否计费。
- **云端**——由托管池计量的会话。这些会话会扣减额度。
- **集群**——同一筛选器在自托管部署上的形式：由你自己的部署所运行的资源池计量的会话，使用该部署自己的模型访问。这里会计入，但背后没有 AgentConnect 余额。
- **Daemon**——由你自行连接的 Daemon 计量的会话。这里会计入，但永远不会计费。

来源在会话运行时记录，因此把一个 Agent 在 Daemon 和资源池之间移动，只会改变其*未来*用量的归属位置，而不会改写历史。

## 谁能看到什么 [#who-sees-what]

| 能力 | 所有者 | 其他成员 |
| --- | --- | --- |
| 查看余额、活动和交易记录 | ✅ | ✅ |
| 查看组织范围的分析总量和来源总量 | ✅ | ✅ |
| 查看分析页面按 Agent / 模型的细分以及随时间变化的支出 | 完整的组织用量 | 仅限他们可访问的 Agent 和会话的用量 |
| 在账单用量行中看到某个 Agent 的名称 | 组织当前的所有 Agent | 仅限他们能看到的 Agent |
| 充值 | ✅ | ❌ |

所有者会获得完整的分析归属，包括来自受限 Agent、其他成员的私密会话或受提供方限制的会话的支出。这些汇总数据不包含会话 ID、标题、会话记录或工具详情。读取某个会话仍然需要通过该会话自己的[会话可见对象](/operate-govern/permissions-overview/session-visibility)。

对于协作者和查看者，分析归属要求同时拥有对 Agent 和会话的访问权限。被扣留的支出仍留在组织总量中，并显示为**受限用量**。已归属的 Agent 行加上该汇总项等于总量。他们的支出图表只包含已归属的用量，因此加总后可能小于组织总量。来源总量对每种角色都保持组织范围。

例如，某个 Agent 在共享会话中有 $4 的支出，在另一位成员的私密会话中有 $7 的支出，那么它为组织总量贡献 $11。所有者会看到全部 $11 都归属于该 Agent。一位可以访问该 Agent 但只能访问共享会话的协作者，会看到 $4 已归属，另有 $7 为未归属用量。
