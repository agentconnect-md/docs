[Computer](/build-your-team/computers) 让 Agent 能够查看和操作图形桌面。控制平面和 Relay 在每次部署中都默认包含基础支持，本页介绍运维人员可以按需开启的配套能力。

| 组成部分                                      | 用途                                             | 默认状态                 |
| --------------------------------------------- | ------------------------------------------------ | ------------------------ |
| [控制台功能](#turn-on-the-console)            | 在控制台中显示 Computer 相关入口                 | 关闭                     |
| [桌面容器](#run-a-desktop-container)          | 在服务器上运行隔离的 Linux 桌面，而非个人电脑    | 未运行                   |
| [STUN 与 TURN](#viewer-video)                 | 浏览器与桌面跨网络时传输实时视频                 | 关闭（查看器轮询截图）   |
| [截图存储](#store-screenshots)                | 保存 Agent 截取的屏幕图片，在会话时间线中展示    | 关闭                     |
| [Computer 池](#cloud-computers-on-kubernetes) | 由部署按需创建的 Cloud Computer                  | 关闭                     |

## 开启控制台功能 [#turn-on-the-console]

在开启 `computer-use` 功能开关前，控制台会隐藏所有 Computer 相关界面，包括**基础设施**下的 **Computer** 分区、单台 Computer 详情页、Agent 工具页的 **Computer** 卡片，以及分析页面的 Computer 用量。

**Helm：**

```yaml
features:
  computerUse: true
```

**Docker Compose：**在 [`compose.env`](/self-hosting/docker-compose/configuration#compose-environment) 的 `FEATURE_FLAGS` 中添加 `computer-use`，然后重建 `web` 容器：

```dotenv
FEATURE_FLAGS=computer-use
```

```bash
docker compose --env-file compose.env up -d --force-recreate web
```

`FEATURE_FLAGS` 是逗号分隔的列表，请保留其中已有的其他开关项。

## 桌面需要访问什么 [#what-a-desktop-must-reach]

桌面端只发起出站连接。无论是个人机器还是桌面容器，都需要以下网络权限：

| 连接目标                                     | 用途                                                       |
| -------------------------------------------- | ---------------------------------------------------------- |
| 控制平面公开 URL（HTTPS 与 WSS）             | 节点注册、状态同步、策略下发和控制权协调                   |
| 每个 Relay 的 Daemon 地址（WSS）             | Agent 工具调用、查看器信令和截图传输                       |
| `github.com`（HTTPS，仅首次启动）            | 下载固定版本并经校验的 ffmpeg，用于查看器实时视频          |
| TURN 服务器（UDP 或 TCP，如已配置）          | 浏览器无法直连桌面时中继视频流                             |

这些地址与 Daemon 使用的地址相同，即 Compose 栈中的 `AGENTCONNECT_PUBLIC_CP_URL` 和 `AGENTCONNECT_RELAY_DAEMON_URL`。如果它们被配置为 `localhost`，则只能从本机访问。在添加其他机器上的桌面之前，请先参考[网络与公开 URL](/self-hosting/docker-compose/configuration#network-and-public-urls) 将服务发布到外部可访问的地址。

## 运行桌面容器 [#run-a-desktop-container]

`computer` 镜像提供一个内置 Chromium、LibreOffice 和常用语言工具链的 Linux 桌面，运行与个人机器相同的桌面守护进程。宿主机需要 `amd64` 或 `arm64` 架构的 Docker 环境、约 2 GB 磁盘空间和 1 至 3 GB 内存。

最快的方式是直接运行**添加 Computer** 的 **Docker** 标签页中提供的 `docker run` 命令（见[添加 Computer](/build-your-team/computers/add-a-computer#docker)）。使用 Docker Compose 则可将配置保存在文件中，升级也只需一条命令：

```bash
mkdir agentconnect-computer && cd agentconnect-computer
base=https://raw.githubusercontent.com/agentconnect-md/agentconnect/main/packages/computer/docker
curl -fsSLO "$base/compose.yaml"
curl -fsSL "$base/compose.env.example" -o .env
```

在控制台中通过**添加 Computer** 生成注册令牌，然后将两项必填配置写入 `.env`：

```dotenv
AGENTCONNECT_CP_URL=https://cp.example.com
AGENTCONNECT_REGISTER_TOKEN=<one-time token>
```

```bash
docker compose up -d
docker compose ps        # STATUS turns (healthy) once the daemon passes its own checks
```

| 配置项                             | 说明                                                               |
| ---------------------------------- | ------------------------------------------------------------------ |
| `AGENTCONNECT_CP_URL`              | 控制平面地址，按控制台显示填写                                     |
| `AGENTCONNECT_REGISTER_TOKEN`      | 一次性注册令牌（首次启动时消耗）                                   |
| `AGENTCONNECT_REGISTER_TOKEN_FILE` | 改为从文件读取令牌，例如使用 Docker secret                         |
| `AGENTCONNECT_COMPUTER_NAME`       | 控制台未填写名称时使用的名称，留空则默认使用主机名                 |
| `AGENTCONNECT_VERSION`             | 镜像标签，建议固定为与控制平面一致的版本                           |
| `AGENTCONNECT_COMPUTER_RESOLUTION` | 屏幕分辨率，默认 `1280x800x24`，与 Agent 截图按 1:1 对应           |
| `AGENTCONNECT_COMPUTER_BROWSER`    | 保持打开并最大化的浏览器，默认 `chromium`，设为 `none` 则不打开    |
| `RTC_ADDRESS`                      | 浏览器访问该服务器的公网 IP，用于直连观看视频                      |
| `AGENTCONNECT_COMPUTER_RTC_PORTS`  | 直连视频发布的 UDP 端口范围，默认 `7700-7709`                      |

数据卷保存了 Computer 的密钥、浏览器配置和文件：

- **升级**：更新 `AGENTCONNECT_VERSION`，然后执行 `docker compose pull && docker compose up -d`。
- **重新注册**：吊销后，将新令牌写入 `.env` 并执行 `docker compose up -d`。
- **移除**：先在控制台中删除该 Computer，再执行 `docker compose down -v`。
- **单机运行多个桌面**：为每个容器分配独立的目录、注册令牌和 UDP 端口范围。

由于 `docker inspect` 会显示容器的环境变量，如对此有安全顾虑，建议优先使用 `AGENTCONNECT_REGISTER_TOKEN_FILE`。令牌一经消耗即失效，无法重复使用。

<Callout type="warn">
容器内运行的 Chromium 未启用自身沙箱，因此容器是唯一的隔离边界。请勿将不应被 Agent 访问的主机目录或凭证挂载进容器。
</Callout>

关于 secret 文件、宿主机网络以及在部署栈同一台主机上试用桌面容器，请参阅仓库中的[桌面容器指南](https://github.com/agentconnect-md/agentconnect/blob/main/docs/self-host-computer-container.md)。

## 观看视频 [#viewer-video]

观看桌面不需要开放任何入站端口：信令和截图通过桌面的出站连接经由 Relay 传输。未做额外配置时，查看器默认以每秒数帧的频率轮询**截图**。如需流畅的实时视频，浏览器和桌面之间需要建立媒体通路：

| 方案              | 效果                                                             | Compose overlay           | Helm values           |
| ----------------- | ---------------------------------------------------------------- | ------------------------- | --------------------- |
| 发布 UDP 端口范围 | 有公网地址的桌面容器直接向浏览器传输视频                         | 容器自身的 `.env`         | —                     |
| Relay 上的 STUN   | 跨 NAT 的点对点视频（Relay 仅协助双方发现彼此地址）              | `compose.stun.yaml`       | `relay.stun`          |
| Relay 上的 TURN   | 无法直连时中继视频（应对对称 NAT 或 UDP 被拦截等环境）           | `compose.relay-turn.yaml` | `relay.turn`          |
| 外部 TURN 服务器  | 通过自建 coturn 或 Cloudflare Realtime TURN 中继（优先级更高）   | `compose.turn.yaml`       | `computerViewer.turn` |

**Relay 上的 STUN**：配置浏览器和桌面可访问的宿主机地址，叠加 overlay 并开放对应的 UDP 端口：

```dotenv
AGENTCONNECT_STUN_HOST=203.0.113.10
# AGENTCONNECT_STUN_PORT=3479
```

```bash
docker compose --env-file compose.env -f compose.yaml -f compose.stun.yaml up -d
```

点对点连接会向观看者的浏览器暴露桌面的公网 IP 地址，因此是否启用由每台 Computer 的**点对点观看**策略决定。

**Relay 上的 TURN**：同时开放该端口的 UDP 和 TCP 流量，无需配置共享密钥或额外端口范围：

```dotenv
AGENTCONNECT_RELAY_TURN_HOST=203.0.113.10
# AGENTCONNECT_RELAY_TURN_PORT=3480
```

```bash
docker compose --env-file compose.env -f compose.yaml -f compose.relay-turn.yaml up -d
```

控制平面会为每个观看者和每个桌面签发短期凭证，Relay 仅在自身分配的会话之间转发视频。对于仅允许 443 端口出站的网络环境，Relay 还支持通过 TLS 提供 TURN 服务。

**外部 TURN 服务器**：使用 `compose.turn.yaml` 可拉起 coturn 并让控制平面指向它：

```dotenv
AGENTCONNECT_TURN_SECRET=<openssl rand -hex 32>
AGENTCONNECT_TURN_EXTERNAL_IP=203.0.113.10
```

请在该宿主机上开放 UDP 和 TCP `3478` 端口以及 UDP `49160-49199`，并且不要在同一地址上运行其他 UDP 服务。如使用 Cloudflare Realtime TURN，改为设置 `COMPUTER_TURN_CLOUDFLARE_KEY_ID` 和 `COMPUTER_TURN_CLOUDFLARE_API_TOKEN` 即可，无需叠加该 overlay。

在 Helm chart 中，`relay.stun` 和 `relay.turn` 会分别为每个 Relay Pod 创建一个 Service，并要求配置公开的 `host`。完整配置项请查阅 [chart README](https://github.com/agentconnect-md/agentconnect/blob/main/charts/agentconnect/README.md)。

## 保存截图 [#store-screenshots]

默认情况下，Agent 截取的屏幕图片仅发送给模型，不会持久化保存。开启截图存储后，截图会显示在会话时间线中，并按每台 Computer 的**截图保留**策略自动清理。图片数据通过签名 URL 从桌面直接上传至对象存储，控制平面仅负责签发 URL 和保存元数据。

**Helm**（需先配置 [Source Cache](/self-hosting/kubernetes/deploy#object-store-source-cache-and-file-transfer) 存储桶）：

```yaml
computerScreenshots:
  enabled: true
  retentionDays: 30     # for a computer whose policy sets none
  maxRetentionDays: 365 # the most a computer's policy may ask for
```

**Docker Compose：**在 `compose.env` 中将 `AC_COMPUTER_SCREENSHOTS` 配置为单行 JSON，存储桶字段与 [`AC_FILE_TRANSFER`](/self-hosting/docker-compose/configuration#external-bucket) 一致，另外可添加可选的 `retention` 对象以设置 `defaultDays` 和 `maxDays`。

过期的截图由控制平面自动清理，无需在对象存储桶上额外配置生命周期规则。

## 在 Kubernetes 上运行 Cloud Computer [#cloud-computers-on-kubernetes]

启用 Helm chart 的 [Daemon 池](/self-hosting/kubernetes/deploy)后，部署还可以按需自动创建桌面。它们在控制台中显示为 **Cloud Computer**：成员可以添加共享桌面，Agent 也可以按会话创建临时桌面或拥有专属的持久桌面。详见 [Cloud Computer](/build-your-team/computers/give-agents-a-computer#cloud-computers)。

```yaml
computerPool:
  enabled: true
```

启用该功能需要同时开启 `daemonPool.enabled` 并配置控制平面的公开 URL（`apiHost` 或 `publicUrl`），以便桌面 Pod 完成注册。

| 配置项                              | 默认值        | 说明                                                           |
| ----------------------------------- | ------------- | -------------------------------------------------------------- |
| `computerPool.warmReplicas`         | `1`           | 预热桌面副本数，让会话在几秒内获得桌面（设为 `0` 则冷启动）    |
| `computerPool.home.size`            | `5Gi`         | 桌面主目录卷大小，休眠期间保留                                 |
| `computerPool.resources`            | 1 Gi 到 3 Gi  | 桌面 Pod 的内存请求和上限                                      |
| `computerPool.ephemeralIdleSeconds` | `600`         | 按会话创建的临时桌面空闲多久后自动删除（秒）                   |
| `computerPool.sleepIdleSeconds`     | `1800`        | Agent 专属桌面或共享桌面空闲多久后自动休眠（秒）               |
| `computerPlan.quotas`               | 内置          | 各组织在并发运行数、持有总数、使用时长和存储上的配额           |

Cloud Computer 的 Pod 不向浏览器暴露 UDP 端口，因此实时观看必须依赖 TURN。请开启 `relay.turn` 或 `computerViewer.turn` 以支持实时视频，否则查看器会回退为轮询截图。

未自定义配额时，每个组织默认最多同时运行 3 台 Cloud Computer、保有 10 台，每月可使用 300 个桌面小时。具体用量可在**分析**页面查看。
