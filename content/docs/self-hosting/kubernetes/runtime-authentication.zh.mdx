Daemon 池会在探测沙箱里启动每个已安装的 Runtime，用来发现可用模型。这个探测过程没有 Agent 身份，因此读不到组织或 Agent 级别的密钥。你可以通过一个集群级 Secret，同时为探测过程和 Agent 会话提供 API 密钥。无人值守的 Runtime 应使用 API 密钥认证，因为池探测里无法完成交互式 OAuth 登录。

## 选择 Runtime 镜像 [#choose-the-runtime-image]

Chart 默认的 `runtime-sandbox` 镜像包含 Claude Code、Codex、DeepSeek Harness 和 OpenCode。已发布的 `runtime-sandbox-full` 镜像在此基础上额外包含 Qwen Code 及其他 ACP Runtime：

```yaml
daemonPool:
  runtime:
    repository: ghcr.io/agentconnect-md/runtime-sandbox-full
```

Chart 会自动拼接对应的 AgentConnect 发布版本标签；如果需要固定完整的镜像地址，使用 `daemonPool.runtime.image`。更换镜像后会重新触发 Runtime 发现。

## 用 Secret 配置任意 Runtime [#configure-any-runtime-with-a-secret]

如果 OpenCode 接入的是 Anthropic、OpenAI 或 DeepSeek，直接使用下方的[内置模型凭证对](#built-in-model-pairs-and-other-sources)即可。已有凭证对会自动复用，不需要单独给 OpenCode 配环境变量映射。接入其他提供方或需要额外 Runtime 配置时，再使用这里的映射方式。

1. 选定模型提供方并获取 API 密钥。查阅对应 Runtime 的官方文档，确认其 API 密钥环境变量名、支持的模型 ID 和端点格式。例如 [Qwen Code 认证](https://github.com/QwenLM/qwen-code/blob/main/docs/users/configuration/auth.md)、[OpenCode 提供方](https://opencode.ai/docs/providers)和 [DeepSeek 的 API 根地址](https://api-docs.deepseek.com/guides/harness)。
2. 把密钥、端点和 Runtime 配置放进 AgentConnect Release 命名空间的 Kubernetes Secret 中，不要把密钥写进 Helm values。
3. 在 `daemonPool.runtimeEnvironment.runtimes` 下，用镜像上报的 Runtime ID，将各 Runtime 的环境变量映射到对应的 Secret 条目。Chart 只会把显式声明的条目投射进 Daemon，在探测和启动会话时也只给每个 Runtime 传入属于它自己的映射变量。
4. 升级 Helm Release。修改映射后会滚动重启 Daemon 池并重新执行探测。如果只是原地修改了 Secret 里的内容，请手动重启 Daemon 池以刷新环境变量和探测结果。

例如，使用 DeepSeek 的 OpenAI 兼容 API 时，可以在 Secret 里放入以下条目：

| Secret 条目 | 值 |
| --- | --- |
| `PROVIDER_API_KEY` | 你的 DeepSeek API 密钥 |
| `PROVIDER_BASE_URL` | `https://api.deepseek.com` |
| `QWEN_MODEL` | `deepseek-flash` |
| `OPENCODE_CONFIG_CONTENT` | `{"model":"deepseek/deepseek-flash","provider":{"deepseek":{"options":{"baseURL":"https://api.deepseek.com"}}}}` |

然后在 Helm values 里引用这些条目，无需把密钥值写进配置：

```yaml
daemonPool:
  runtime:
    repository: ghcr.io/agentconnect-md/runtime-sandbox-full
  runtimeEnvironment:
    existingSecret: agentconnect-model-credentials
    runtimes:
      qwen-code:
        OPENAI_API_KEY: PROVIDER_API_KEY
        OPENAI_BASE_URL: PROVIDER_BASE_URL
        OPENAI_MODEL: QWEN_MODEL
      opencode:
        DEEPSEEK_API_KEY: PROVIDER_API_KEY
        OPENCODE_CONFIG_CONTENT: OPENCODE_CONFIG_CONTENT
```

Qwen Code 会根据 `OPENAI_API_KEY` 走 OpenAI 兼容的 API 密钥认证。OpenCode 则从 `OPENCODE_CONFIG_CONTENT` 读取 `deepseek` 提供方和默认模型，并从环境变量里读取 `DEEPSEEK_API_KEY`。上面的端点和模型基于 [DeepSeek 当前的 API 文档](https://api-docs.deepseek.com/guides/harness)；如果接入其他服务，请以对应提供方的文档为准。这两个 Runtime 都不需要浏览器登录或保存 OAuth 账号。

OpenCode 的 `model` 字段只指定默认模型，不会限制可用提供方列表。如果要接入内置凭证对之外的提供方，把 API 密钥放进 Secret，并在 `opencode` 下映射对应变量（例如 [OpenCode Zen](https://opencode.ai/docs/zen) 的 `OPENCODE_API_KEY`）。如果同时配置了内置凭证对，需要在 `OPENCODE_CONFIG_CONTENT` 的 `enabled_providers` 里显式加上这些额外的提供方。另外，模型出现在目录里并不代表你的账号一定有权调用，请用对应凭证发一次测试请求确认。

如果 `daemonPool.modelCredentials.existingSecret` 已经指向同一个 Secret，可以省略 `runtimeEnvironment.existingSecret`。每条映射填写的是 Secret 里的**条目名**，不是内联值。如果条目缺失或为空，Daemon 会在启动时直接报错，不会在缺少凭证的情况下静默探测。Runtime 映射会覆盖同名的 Agent 级变量，而内置模型转换和已签发会话密钥对其写入的变量继续保留原有优先级。

## 内置模型凭证对与其他来源 [#built-in-model-pairs-and-other-sources]

Chart 也通过 `daemonPool.modelCredentials.existingSecret` 支持内置凭证转换：

| Runtime | 令牌条目 | 基础 URL 条目 |
| --- | --- | --- |
| Claude Code 与 OpenCode 的 `anthropic` 提供方 | `ANTHROPIC_MODEL_TOKEN` | `ANTHROPIC_MODEL_BASE_URL` |
| Codex 与 OpenCode 的 `openai` 提供方 | `OPENAI_MODEL_TOKEN` | `OPENAI_MODEL_BASE_URL` |
| DeepSeek Harness 与 OpenCode 的 `deepseek` 提供方 | `DEEPSEEK_MODEL_TOKEN` | `DEEPSEEK_MODEL_BASE_URL` |

`MODEL_TOKEN` 和 `MODEL_BASE_URL` 可作为这些受支持 Runtime 的共享回退项。配置了某个 Runtime 专用的凭证对后，它会整体替代共享凭证对。Daemon 会在探测和启动时把凭证对转换成对应 Runtime 的配置，但不会为 Qwen Code 或其他任意 Runtime 做自动转换。这类 Runtime，或者模型选择、提供方配置等超出密钥和 URL 范围的设置，请使用 `runtimeEnvironment`。

OpenCode 默认启用通过这些凭证对配置的提供方，同时保留 `OPENCODE_CONFIG_CONTENT` 里显式设置的 `enabled_providers`、模型限制和自定义模型定义。Anthropic 会直接复用 Claude Code 的基础 URL：AgentConnect 会为 OpenCode 的 SDK 自动补上 `/v1`，如果已有该后缀则不重复拼接。OpenAI 和 DeepSeek 的基础 URL 保持原样透传。

如果接入了密钥服务器，模型发现阶段只需要提供含端点的凭证对即可。发现过程本身不发起模型调用，实际会话启动时会按所选提供方签发临时密钥。跨提供方切换会在当前任务结束、下次 Runtime 启动时生效，并使用新提供方的密钥。不接密钥服务器时，OpenCode 会拿到各个提供方独立的静态密钥，可以直接在已配置的提供方之间切换。

`modelEgress.clients` 是面向受支持客户端的另一种集群级配置来源。Chart 不允许同时配置 `modelEgress.clients` 和 `modelCredentials.existingSecret`，也不允许在 `daemonPool.extraEnv` 里重复设置内置凭证对。组织和 Agent 级别的[变量与密钥](/build-your-team/variables-and-secrets)只会下发给对应的 Agent 会话，不会进入独立的池探测。**基础设施 → Provider keys** 保存的是面向受支持消费者的组织级连接，不是 ACP Runtime 的凭证。

OpenCode 同样会复用 `modelEgress.clients.claude`、`.codex` 和 `.deepseek` 提供的凭证对。启用 OpenCode 时无需改动这些配置，也不需要单独建一个 `opencode` 客户端条目。

对接 Codex 网关时，将 `OPENAI_MODEL_TOKEN` 和 `OPENAI_MODEL_BASE_URL` 指向该网关的 Codex 兼容 API 根地址，Daemon 会同时为 Codex 配好提供方 URL 和 API 密钥。如果直连 DeepSeek，使用其[文档中的 API 根地址](https://api-docs.deepseek.com/guides/responses_api/) `https://api.deepseek.com`。

部署完成后，可以查看 Daemon 池的探测完成日志，再到控制台检查对应 Runtime 的模型选择器来确认发现结果。即使镜像里已经装了某个 Runtime，只要它的 API 密钥、模型 ID 或端点配置有误，选择器依然可能是空的。

## 密钥留在 Daemon 池中 [#keys-stay-with-the-daemon-pool]

当模型提供方端点使用 HTTPS 时，集群配置的静态密钥不会进入 Agent Pod。Daemon 池从自己的环境中读取真实密钥，给 Pod 里的 Runtime 下发占位符，并在每次发往提供方的出站请求中自动替换为真实密钥。这一机制仅涵盖本 Chart 配置的密钥，包括 `modelCredentials` 中的内置凭证对、`modelEgress.clients.<client>.apiKey`，以及在 `runtimeEnvironment` 下映射的 `ANTHROPIC_API_KEY`、`OPENAI_API_KEY`、`DEEPSEEK_API_KEY` 和 `COPILOT_PROVIDER_API_KEY`。

- Daemon 池必须能通过 HTTPS 访问这些密钥对应的提供方端点或网关。如果集群限制了 Release 命名空间的出站流量，请放行这些目标地址。
- 在以下情况中，密钥仍会留在 Pod 环境里：端点使用明文 `http://`、Daemon 无法为该 Runtime 确定唯一端点，或者其他变量里也包含了该密钥（例如在 `OPENCODE_CONFIG_CONTENT` 中内嵌了密钥）。触发该回退时，Daemon 会打印一次日志提示。
- 密钥服务器签发的密钥和模型发现探测过程不受影响。

其他 Daemon 上的同类行为见[凭证保护](/operate-govern/sandboxing/credential-protection#provider-api-keys)。
