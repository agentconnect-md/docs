以下操作面向已经运行的 Helm Release。首次安装请参阅[使用 Helm 部署](/self-hosting/kubernetes/deploy)。

## 升级 [#upgrade]

升级前请先备份 PostgreSQL 和重要的工作区 PVC，选好目标版本并查看发布说明。由于 Helm 不会自动升级 Chart `crds/` 目录下的 CRD，请先应用对应版本的 CRD，再升级控制器和应用服务：

```bash
export AGENTCONNECT_NEW_CHART_VERSION=X.Y.Z
export AGENTCONNECT_CHART_DIR="$(mktemp -d)"

helm pull oci://ghcr.io/agentconnect-md/charts/agentconnect \
  --version "$AGENTCONNECT_NEW_CHART_VERSION" \
  --untar \
  --untardir "$AGENTCONNECT_CHART_DIR"

kubectl apply --server-side \
  -f "$AGENTCONNECT_CHART_DIR/agentconnect/crds/agent-sandbox.yaml"

helm upgrade agentconnect \
  oci://ghcr.io/agentconnect-md/charts/agentconnect \
  --version "$AGENTCONNECT_NEW_CHART_VERSION" \
  --namespace agentconnect \
  --values agentconnect-values.yaml \
  --wait \
  --timeout 15m
```

Chart 版本会自动匹配对应版本的应用镜像。除非你刻意要部署混合版本，否则把 `image.tag` 和各组件镜像标签留空即可。

## 孤立对象清理 [#orphan-cleanup]

Daemon 池内置了一个定时运行的调谐器，用来清理对应 Agent 已不存在的沙箱对象，默认处于 dry-run（试运行）模式。建议先观察一段时间的运行摘要，确认无误后再设置 `daemonPool.reconciler.delete: true`。删除孤立的沙箱 claim 会一并删掉它的工作区 PVC，且无法恢复。

## 共享集群中的控制器归属 [#shared-cluster-controller-ownership]

`agent-sandbox` CRD 和控制器是集群级共享资源。在独立集群中，单个 AgentConnect Release 可以直接管理它们。如果多个 AgentConnect Release 共用同一个集群，请在这些 Release 之外统一维护 CRD 和控制器，安装每个 Chart 时加上 `--skip-crds` 并设置 `installCRD: false`，避免多个 Helm Release 争抢同一套集群级控制器。

## 故障排查 [#troubleshooting]

- **Pod 停留在 `ContainerCreating`**：执行 `kubectl describe pod` 排查，常见原因是缺少 `agentconnect-secrets` 或 `agentconnect-data-plane` Secret。
- **Daemon 池成员一直未就绪（Not Ready）**：查看 Pod 日志，检查数据平面的 PostgreSQL 连接串、`agent-sandbox` 控制器以及 Runtime 预热池是否正常。
- **沙箱 Pod 停留在 `Pending`**：核对配置的 StorageClass、节点架构、集群资源余量、节点选择器和容忍度。
- **HTTPRoute 未被 Accepted**：查看它的状态详情，以及 Gateway 监听器的主机名、`sectionName` 和允许接入的命名空间配置。
- **在 Setup 保存配置后，控制台仍不显示登录按钮**：控制台会在启动时缓存控制平面的配置快照。请在控制平面变为 Ready 后重启控制台。
- **Agent 提示其 Runtime 需要认证**：Runtime 没有拿到模型凭证。检查该 Agent 和组织的变量配置，如果启用了全局凭证，也检查 `daemonPool.modelCredentials`。
- **Agent Pod 发起的模型或 Git 请求连接失败**：这类请求由 Daemon 池代为发出。确认 Daemon 池能通过 HTTPS 访问对应的模型端点和代码托管平台。
- **登录后控制台返回 `401`**：检查 Logto 的 API Resource 是否与控制平面的 audience 完全一致，详见[登录](/self-hosting/sign-in#verify-the-setup)。

完整的配置项说明和仅部署控制平面的示例，见 Chart 的 [README](https://github.com/agentconnect-md/agentconnect/tree/main/charts/agentconnect)。
