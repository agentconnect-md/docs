Docker Compose 服务栈适合在单台机器上运行 AgentConnect 做本地评估，Daemon 则部署在你自己管理的机器上。如果要部署到集群，请参阅[使用 Helm 部署](/self-hosting/kubernetes/deploy)。

## 开始之前 [#before-you-start]

请先准备：

- Docker Desktop、OrbStack 或 Docker Engine
- Docker Compose v2（`docker compose version`）
- Git

目前发布的 AgentConnect 镜像均为 `linux/amd64` 架构。在 Apple Silicon 设备上，Docker Desktop 和 OrbStack 可以通过模拟运行。

## 1. 启动服务栈 [#1-start-the-stack]

```bash
git clone https://github.com/agentconnect-md/agentconnect.git
cd agentconnect
docker compose up -d --pull always
```

如果想从本地代码构建镜像，而不是拉取已发布镜像，运行 `docker compose up -d --build`。`compose.yaml` 中的每个服务都配置了构建定义，构建产物会直接使用服务栈引用的镜像标签。本地构建同样面向 `linux/amd64`，因此在 Apple Silicon 上会走模拟执行，耗时较长。

首次启动会拉起 PostgreSQL 18、执行数据库迁移、初始化本地无认证组织，并启动各应用服务，不会写入任何示例数据。内置的 `agentconnect` Agent 默认开启，如需关闭可在 [Setup](/self-hosting/docker-compose/configuration#setup-server) 中禁用。

检查运行状态：

```bash
docker compose ps --all
```

`postgres`、`control-plane`、`relay`、`setup-server` 和 `web` 应处于运行状态。`migration-files` 和 `migrate` 是一次性任务，正常完成后应显示 `Exited (0)`。

## 2. 打开 AgentConnect [#2-open-agentconnect]

在浏览器中打开 [http://localhost:3000](http://localhost:3000)。

默认配置下，所有端口都只绑定在 `127.0.0.1`，且未开启登录。请仅在本地使用该模式。

也可以直接检查各服务的就绪探针：

```bash
curl http://localhost:8080/readyz
curl http://localhost:8090/readyz
```

## 3. 连接 Daemon [#3-connect-a-daemon]

Compose 服务栈不会把 Daemon 放进容器里运行。把它留在宿主机上，Agent 才能直接访问本地代码仓库、Runtime 启动器以及已有的 Claude 或 Codex 认证。

在 Web 控制台中：

1. 打开**基础设施**，选择**添加 Daemon**。
2. 复制生成的一次性命令。
3. 在需要运行 Agent 的机器上原样执行该命令。

Daemon 通过出站连接接入控制平面和 Relay。如果 Daemon 运行在另一台机器上，请先配置其他主机可访问的 URL，详见[网络与公开 URL](/self-hosting/docker-compose/configuration#network-and-public-urls)。

## 引导式设置 [#guided-setup]

如果除了本地跑通，还要继续配置登录、公开 URL、提供方应用和生产加固，可以使用仓库自带的引导技能。该技能位于 `.claude/skills/agentconnect-setup`，同时暴露在 `.agents/skills` 下，Claude Code、Codex 等编码 Agent 都能自动识别。

在代码目录里启动你的编码 Agent，让它帮你配置 AgentConnect。它会按本页和后续部署文档逐步引导操作，每完成一个检查点都会先做验证，且不会要求你在聊天里粘贴密钥。

下面各节介绍了对应的手动步骤。无论是否使用该技能，都可以把它们当作配置参考。

## 可选：添加本地登录 [#optional-add-local-sign-in]

仓库提供了一个 Logto OSS 叠加配置（overlay），不用配 DNS 或 TLS 就能体验真实登录流程：

```bash
docker compose -f compose.yaml -f compose.logto.yaml up -d
```

启动后打开以下地址：

- Setup：[http://localhost:8091](http://localhost:8091)
- Logto Console：[http://localhost:3002](http://localhost:3002)
- AgentConnect：[http://localhost:3000](http://localhost:3000)

接着按[登录](/self-hosting/sign-in)中的步骤完成配置，本地测试用 Google 登录最快。该叠加配置会在同一个 PostgreSQL 实例里为 Logto 建一个独立数据库，并且依然只绑定回环地址。

使用叠加配置后，后续执行 `up`、`pull` 和 `down` 时都需要带上这两个 `-f` 参数。

如果是生产环境，请跳过这个叠加配置，直接接入 [Logto Cloud 租户](/self-hosting/sign-in#logto-cloud)。

## 日志与更新 [#logs-and-updates]

实时查看服务栈日志：

```bash
docker compose logs -f
```

拉取最新镜像并执行迁移：

```bash
docker compose pull
docker compose up -d
```

如果你创建了 `compose.env`，请在每条命令里加上 `--env-file compose.env`。把 `AGENTCONNECT_VERSION` 固定到具体的发布标签，可以保证部署结果可复现。

## 停止或重置 [#stop-or-reset]

停止服务栈并保留数据库：

```bash
docker compose down
```

删除数据库并回到初始空状态：

```bash
docker compose down --volumes
```

> 这会永久删除 Compose 数据库中的控制平面和 Setup Server 数据。Daemon 本地的工作区和会话记录不在该数据卷内，不会被删除。

## 服务栈包含哪些组件 [#what-the-stack-includes]

| 组件 | 位置 | 用途 |
| --- | --- | --- |
| Web 控制台 | Docker | 配置并跟进工作 |
| 控制平面 | Docker | 认证与协调数据 |
| Relay | Docker | 公开回调入口 |
| Setup Server | Docker，仅回环地址 | 配置部署认证与提供方应用 |
| PostgreSQL | Docker | 持久化部署和控制平面数据 |
| Logto OSS | 可选叠加配置 | 本地登录 |
| 对象存储（RustFS） | HTTPS 叠加配置 | 文件上传和大文件工作区下载（见[文件传输](/self-hosting/docker-compose/configuration#file-transfer-and-the-object-store)） |
| Daemon | 宿主机或另一台机器 | 运行 Agent 并保存本地数据 |

内置 Relay 后，GitHub、Webhook、网页聊天和 HTTP 机器人回调无需改动架构即可工作。Slack Socket Mode、Telegram、Discord 和 Lark / 飞书的直连仍然直接在 Daemon 和各自平台之间建立。

## 部署边界 [#deployment-boundary]

自带的 Compose 拓扑面向本地评估和单机部署。对外暴露到网络之前，请开启真实登录、替换默认密钥、启用 TLS、做好 PostgreSQL 备份，并在反向代理上配置 WebSocket 支持。
